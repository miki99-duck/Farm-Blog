# 第 1 章 · 环境准备与第一次对话

> 本章目标:搭好环境,理解 ChatModel 的调用模型(invoke/stream)、三种消息角色,
> 并亲手验证一个关键事实——**模型本身没有记忆**。
>
> 对应 demo:`hello_llm.py`、`stream_chat.py`、`messages_multi_turn.py`

---

## 1. 环境准备(一次性)

### 1.1 安装依赖

要求 Python 3.10+(LangChain 1.0 的最低版本)。

先认识三条命令里的小名词:

- **虚拟环境**:给本项目专用的独立工具箱(一个 `.venv` 文件夹),里面装的东西不影响电脑上其他项目;
- **pip**:Python 自带的"应用商店",负责安装库;
- **requirements.txt**:要安装的库的购物清单,`pip install -r` 照单全收。

```bash
# 建议先创建虚拟环境(任选其一)
python -m venv .venv
# Windows: .venv\Scripts\activate   macOS/Linux: source .venv/bin/activate

pip install -r requirements.txt
```

本章实际只用到 `langchain`、`langchain-openai`、`python-dotenv` 三个包。

### 1.2 配置 API Key

1. 到[智谱开放平台](https://open.bigmodel.cn/usercenter/apikeys)注册并创建 API Key;
2. 复制 `.env.example` 为 `.env`,填入 Key:

```bash
cp .env.example .env      # Windows 用 copy 命令或直接在编辑器里另存
```

**`.env` 是什么?** 一个普通的文本文件,专门放"钥匙"(API Key)这类敏感配置,让代码里不出现任何密码。
程序通过"环境变量"读取它——环境变量可以理解为"程序启动时顺手带上的配置便签"。
你只需照抄:把 `.env` 放在项目根目录,`shared/llm.py` 已经写好了读取逻辑。

`.env` 中与本章相关的两项:

```ini
ZHIPU_API_KEY=你的key        # 必填
LLM_MODEL=glm-4-flash        # 默认免费档;要更强可改 glm-4.6 等
```

> **模型名失效怎么办?** 模型迭代快,若运行报"模型不存在",去智谱控制台看当前可用型号,
> 改 `.env` 一行即可——这正是把模型名放进 `.env` 而不是写死在代码里的原因。

### 1.3 统一的模型入口:shared/llm.py

全教程所有 demo 都通过 `shared/llm.py` 拿模型,核心就这几行:

```python
from langchain_openai import ChatOpenAI

GLM_BASE_URL = "https://open.bigmodel.cn/api/paas/v4/"

llm = ChatOpenAI(
    model="glm-4-flash",       # .env 的 LLM_MODEL
    api_key="你的智谱key",      # .env 的 ZHIPU_API_KEY
    base_url=GLM_BASE_URL,     # 关键:指向智谱的 OpenAI 兼容端点
    temperature=0.7,
)
```

**为什么用 `ChatOpenAI` 接智谱?** 智谱实现了 OpenAI 兼容协议,LangChain 官方也推荐这样做。
好处是:这套写法学会后,接 DeepSeek 只需换 `base_url="https://api.deepseek.com/v1"` 和模型名,
接 Qwen、Kimi 同理。你学的是"OpenAI 兼容生态"的通用技能,而不是绑死一家的私有 SDK。

## 2. ChatModel 的三个调用方法

**ChatModel** 就是"对话模型"在 LangChain 里的统一叫法。不管接智谱还是 OpenAI,调用方式完全一样,
最常用的三个方法:

| 方法 | 返回 | 用途 |
|------|------|------|
| `llm.invoke(x)` | 一条完整的 AI 消息 | 普通调用 |
| `llm.stream(x)` | 逐块的迭代器 | 打字机效果、降低首字延迟 |
| `llm.batch([...])` | 结果列表 | 一次并发处理多条输入(第 4 章演示) |

### 2.1 Demo 1-1 · hello_llm.py:最小调用

```python
from shared.llm import get_llm

llm = get_llm()
response = llm.invoke("用一句话向一位刚接触大模型的程序员介绍你自己。")
print(response.content)
```

要点:

- `invoke` 收到字符串时,内部自动包装成一条用户消息;
- 返回值是 `AIMessage` 对象,**取 `.content` 才是文本**,直接打印对象会带上一堆元数据;
- 元数据(metadata,即"附带的说明信息")里还有 `response_metadata`(含消耗 token 数、请求 id 等)——token 就是第 0 章说的"计费字块",排查费用问题时有用。

**预期输出**(内容每次不同):

```
模型:glm-4-flash
回复:我是一个 AI 助手,可以帮你回答问题、写代码、处理文本等任务。
```

### 2.2 Demo 1-2 · stream_chat.py:流式输出

```python
for chunk in llm.stream(question):
    print(chunk.content, end="", flush=True)
```

LLM 是逐 token 生成的,`stream` 让每个生成块立刻送到你手里:

- 体验差异巨大:整段生成要 3-5 秒,流式让**首字**在几百毫秒内出现;
- 每个 `chunk.content` 只有一小截文字,循环打印拼成完整回答;
- `end=""` + `flush=True` 是让终端产生"打字机效果"的小技巧;
- 生产环境中,Web 后端会把 `stream` 接到 SSE/WebSocket 上推给前端——这两个名字指"网页持续接收服务器推送"的技术,现在知道有这回事即可(第 10 章实战)。

### 2.3 Demo 1-3 · messages_multi_turn.py:消息类型与"失忆"实验

对话模型吃的是**消息列表**,三种角色各司其职:

```
SystemMessage   → 设定人设与规则("你是简洁的 Python 导师"),用户看不到
HumanMessage    → 用户说的话
AIMessage       → 模型的话(多轮对话里代表"历史回复")
```

多轮对话的本质是:**每次请求都把完整历史重发一遍**:

```python
messages = [
    SystemMessage(content="你是一位说话简洁的 Python 导师。"),
    HumanMessage(content="什么是列表推导式?"),
    AIMessage(content="用一行 for 循环生成列表的写法。"),
    HumanMessage(content="给个例子"),   # 模型能接上,因为上文都在
]
reply = llm.invoke(messages)
```

demo 的第二部分做了一个**反例实验**:只发 `["给个例子"]`。模型会答非所问——
它根本不知道你之前问过"列表推导式"。这个实验验证了第 0 章的分析:

> **模型是"失忆"的。所谓多轮对话,是你每次都把历史抄送给它。**

"AI 记得我"是一种错觉。谁管理这份历史、历史太长怎么办,就是第 5 章"记忆管理"的全部内容。

## 3. 常用参数速查

`ChatOpenAI(...)` 构造参数(都可通过 `get_llm(**kwargs)` 传入):

| 参数 | 作用 | 建议 |
|------|------|------|
| `temperature` | 随机度 0~1,越高越发散 | 聊天 0.7;**抽取/分类务必 0** |
| `max_tokens` | 回复长度上限 | 防跑飞、控成本 |
| `timeout` | 请求超时秒数 | 生产环境必设 |
| `max_retries` | 自动重试次数 | 默认 2,可加大 |

另外注意 `llm.model_name` 属性可以确认当前用的模型,排查"改了 .env 没生效"时先看它。

## 4. 常见坑

1. **Key 写进代码提交到 Git** —— 一旦泄漏,轻则刷爆额度。永远用 `.env` + `python-dotenv`,`shared/llm.py` 已帮你处理;
2. **忘记 `.env` 在项目根目录** —— `shared/llm.py` 会自动按项目根查找,但如果自己另开目录运行,注意 `load_dotenv` 找不到文件时**静默跳过**;
3. **直接 `print(response)`** —— 拿到的是消息对象,记得 `.content`;
4. **`stream` 的 chunk 也可能是空的** —— 个别块 `content` 为空字符串,打印无害,但拼接前最好跳过;
5. **模型名过时** —— 前面说过,报模型不存在就换 `.env`。

## 5. 小结与练习

本章你学会了:配置 → 最小调用 → 流式 → 消息类型 → "模型无记忆"的实证。
