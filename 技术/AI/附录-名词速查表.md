# 附录 · 名词速查表

> 全教程术语的白话解释 + 生活类比。**遇到不懂的词就来查**,不用按顺序读。
> 标注"→ 第 X 章"表示该名词在对应章节有手把手实操。

## 一、大模型基础

| 术语 | 白话解释 |
|------|----------|
| 大模型 / LLM | "读过海量文本、擅长接话的 AI 大脑",只做"读文字、吐文字"一件事。ChatGPT、智谱 GLM 都是 |
| 提示词(prompt) | 你发给模型的指令文字,如"帮我总结这段话" |
| 上下文窗口 | 模型一次最多能"读进脑子"的文字量,按 token 算。类比书桌大小 |
| token | 模型计费和计长的"字块",大致相当于 1 个汉字(英文约半个单词一块) |
| 幻觉 | 模型一本正经地编造不存在的信息。是概率生成的天性,只能靠工程手段压制 |
| 温度(temperature) | 随机度旋钮(0~1):越低输出越稳定(适合抽取、分类),越高越发散(适合创作) |
| 消息角色 | 对话里的三种"说话人":system(给模型定规矩,用户看不见)、user(用户)、assistant/AI(模型) |
| 多轮对话 | 连续问答。本质是你**每次都把全部历史抄送**给模型——模型本身没有记忆 |
| 流式输出 | 模型边生成边往外吐字,像打字机,不用等整段说完 |
| 向量 / 嵌入(embedding) | 把一段文字变成一长串小数(文字的"语义坐标")。意思相近的文字,坐标也相近 |
| 余弦相似度 | 给"两个向量方向有多接近"打分(0~1,越接近 1 越像)。名字唬人,不需要懂数学 |
| 微调(fine-tuning) | 用自己的数据重新训练模型。贵且慢;本教程用 RAG 代替,换文档就换知识 |

## 二、开发环境

| 术语 | 白话解释 |
|------|----------|
| Python | 本教程使用的编程语言,语法接近自然语言 |
| 库 / 包 | 别人写好的代码合集,装上就能用,类比手机 App |
| 依赖 | 你的项目需要用到的一堆"库",一环扣一环 |
| pip | Python 自带的"应用商店",负责安装库 |
| requirements.txt | 要安装的库的购物清单,`pip install -r` 照单全收 |
| 虚拟环境 | 给本项目专用的独立工具箱(一个文件夹),不影响电脑上其他项目 |
| 终端 / 命令行 | 敲命令操作电脑的黑窗口。Windows 的 PowerShell、macOS 的 Terminal 都是 |
| 环境变量 | 程序启动时顺手读取的"配置便签" |
| `.env` | 存放配置便签的文本文件,专放 API Key 这类敏感信息,不进代码、不传 Git |
| API Key(密钥) | 你的专属"密码",证明请求是你发的、费用记你账上。泄露=别人刷你的钱 |
| 类型标注 | 代码里 `x: str` 这类写法,作用是说明书:"这个参数应该传字符串"。不影响运行 |

## 三、网络与服务

| 术语 | 白话解释 |
|------|----------|
| API | 程序之间的"点菜窗口":递请求进去,拿结果出来 |
| SDK | 官方写好的"点菜工具包",照说明书调函数即可,不用懂窗口规矩 |
| 端点(endpoint) | 点菜窗口的**网址**,如智谱的 `https://open.bigmodel.cn/api/paas/v4/` |
| base_url | LangChain 里"窗口地址"参数。改成智谱的地址,就能用 OpenAI 的写法调 GLM |
| OpenAI 兼容 | 某厂商把自家窗口"伪装"成 OpenAI 的规矩。会一套写法,DeepSeek/Qwen/Kimi 通吃 |
| JSON | 一种"键值对"格式的文本,程序间传数据的通用格式,长得像 `{"名字": "小明"}` |
| HTTP | 浏览器和网站服务器之间说话的规矩。POST=递交数据,GET=索取数据 |
| FastAPI / uvicorn | 用 Python 快速搭"网站后台服务"的流行工具(一个负责功能,一个负责开门营业) |
| 进程 / worker | "一个正在运行的程序副本"。开 4 个 worker = 4 个服务员同时接客 |
| 灰度发布 | 新版本先只放给 5% 用户试用,没问题再全量,翻车损失小 |
| 探活 | 定期询问服务"还活着吗"的检查接口(本教程的 /health) |

## 四、LangChain 全家桶

| 术语 | 白话解释 |
|------|----------|
| 框架(framework) | 别人搭好的"毛坯房带水电":公共工程铺好,你只管放家具(写业务逻辑) |
| langchain-core | 零件的"插头标准":规定所有零件长同一种样子、能互相拼接 |
| langchain | 用标准零件做好的"现成好物"(如 create_agent) |
| langgraph | "画流程图"的引擎:流程会拐弯、回头、等人时用它 |
| LangSmith | 官方"监控后台"(网页服务),看每次调用的来龙去脉和花费 |
| 集成包(langchain-xxx) | 对接具体厂商的"转接头":接模型、接向量库各一个包 |
| ChatModel | "对话模型"在 LangChain 里的统一叫法 |
| ChatOpenAI | 统一调用入口(名字带 OpenAI 是因为走它的通用协议),接 GLM 也用它 |
| 消息(Message) | 对话的一条记录,带角色和内容 |
| 提示词模板 | 带空格的固定话术,如"把{topic}翻译成英文",用时填空 |
| few-shot(少样本) | 在提示词里放几组"输入→期望输出"的示例,让模型照猫画虎 |
| 链(chain) | 用 `|` 把零件串成的流水线:输入从第一环流向最后一环 |
| Runnable | "可运行的东西"——所有零件遵守的统一标准(都会 invoke/batch/stream),所以能任意拼接 |
| LCEL | LangChain 的拼接语法,核心就是管道符 `|`,像接水管 |
| invoke / batch / stream | 三种执行动作:单个跑 / 一批并发跑 / 流式跑 |
| 解析器(parser) | 流水线末端的"剥壳器",如把模型消息对象剥成纯文本 |
| RunnableParallel | "多路并发"零件:一份输入同时喂给多条分支,谁也不等谁 |
| RunnableBranch | "岔路口"零件:按条件选一条路走 |
| 重试(retry) | 失败了自动再试几次,对付网络抖动、临时限流 |
| 降级(fallback) | 主力方案彻底失败时,自动换备用方案顶上 |
| 检索器(Retriever) | "找资料"的标准接口:只认"问题进、资料出",底层换成什么库都行 |

## 五、RAG 相关

| 术语 | 白话解释 |
|------|----------|
| RAG | 检索增强生成:先查资料,再让模型"看着材料回答"。类比开卷考试 |
| 文档(Document) | LangChain 里一篇资料的载体:正文 + 来源信息 |
| metadata(元数据) | 附在资料上的"标签",如来自哪个文件。回答标注出处靠它 |
| 切分(chunk) | 把长文档剪成小块,方便检索。chunk 就是"小块" |
| chunk_size / overlap | 每块的目标长度 / 相邻块重叠的长度(防止关键句被拦腰剪断) |
| 向量库 | 专门存"语义坐标"并能快速找相似的仓库,本教程用 Chroma |
| 相似度检索 | "按意思找"而非"按字面找":问题与资料的坐标越近越相关 |
| top_k | 一次取最相关的前 k 块资料 |
| 引用溯源 | 回答时标注"这条信息来自哪份文档",让答案可查证 |
| 混合检索 | 向量(按意思)+ 关键词(按字面)两路一起找,对付型号、人名等精确词 |
| 重排(rerank) | 先宽召回 20 条,再用打分模型精选 3 条,显著提升准确率 |

## 六、Agent 与 LangGraph

| 术语 | 白话解释 |
|------|----------|
| 工具(tool) | 你写的一个普通函数,登记给模型后,它"点菜"让你执行 |
| 工具调用(tool calling) | 完整流程:登记工具→模型点菜(tool_calls)→你执行→结果回传→模型收尾 |
| Agent(智能体) | 会自主决定"下一步干什么"的模型 + 工具组合:点菜→吃菜→再点菜→……→交付 |
| create_agent | LangChain 1.0 一行创建智能体的标准入口 |
| MCP | 一套公开标准,把工具打包成"即插即用"的服务,不同 AI 软件都能共用 |
| 状态图(StateGraph) | LangGraph 的流程图:站点(节点)+ 箭头(边)+ 一块共享黑板(状态) |
| 状态(State) | 流程图上的"共享黑板",每个节点都能读、能往上面写几笔 |
| 节点(node) | 图上的一个步骤(一个函数):读黑板,干活,把结果写回黑板 |
| 边 / 条件边 | 固定边=走完必去下一站;条件边=路由函数看黑板决定去哪,甚至回头 |
| TypedDict | Python 自带的标注写法,给"黑板上的每个格子"注明类型,让人一眼看懂 |
| checkpointer(检查点) | 每走一步自动存档,像游戏存档。暂停、恢复、断点续跑都靠它 |
| interrupt / 人工把关 | 流程中途暂停,把问题抛给人类;人批复后从暂停点继续 |
| supervisor | 多智能体的一种分工模式:一个"主管"看黑板派活,工人干完回来汇报 |
| recursion_limit | 图的"最多走多少步"上限,防止模型派活派到天荒地老 |
| 可观测性 | 给每次调用装"行车记录仪":用了什么提示词、查了什么资料、花了多少钱,全程留痕 |
| 回归测试 | 改了代码/提示词后,用攒好的题库重考一遍,确保没把原来对的改错 |
