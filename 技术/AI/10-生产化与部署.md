## 1. Demo 10-3 · langsmith_tracing.py:可观测(建议先读这节)

**为什么排障需要它**:线上用户反馈"机器人答错了",你需要的不是猜,而是还原现场:
那次调用的完整提示词、检索到的资料、模型原话、token 花费、耗时。
LangSmith 是 LangChain 官方的追踪/评估平台,**接入零代码**——配好环境变量即自动上报:

```ini
# .env
LANGSMITH_TRACING=true
LANGSMITH_API_KEY=你的key
LANGSMITH_PROJECT=langchain-glm-tutorial
```

注册 [smith.langchain.com](https://smith.langchain.com)(有免费额度)拿 Key,重跑任意一个前面的 demo,
后台立刻能看到完整的调用树。它提供三类能力:

1. **追踪(Tracing)**:每次 invoke 的输入输出、每条链/每个节点的耗时与 token 数;
2. **数据集与评估(Evaluation)**:把"问题-标准答案"攒成数据集,改了提示词/换了模型后批量重考一遍(**回归测试**:确保没把原来对的改错),
   RAG 答对率从"感觉变好了"变成"从 72% 提升到 89%";
3. **监控(Monitoring)**:错误率、延迟分布、成本曲线。

**成本提示**:追踪上报的是提示词与输出文本,涉密场景先评估合规要求,或自建 Langfuse 等开源替代
(接口思路相同)。没配 LangSmith 时 demo 会优雅降级,照常运行。

## 2. Demo 10-2 · cache_retry_rate_limit.py:省钱与保命

### 2.1 缓存:同一问题只付一次钱

```python
from langchain_core.caches import InMemoryCache
from langchain_core.globals import set_llm_cache

set_llm_cache(InMemoryCache())   # 一行开启,此后所有 LLM 调用自动查缓存
```

命中条件是**完整的提示词 + 模型参数一致**。demo 里第二次同样的问题耗时从秒级降到毫秒级,
且**不消耗 token**。注意:temperature=0.7 的两次调用结果本该不同,但缓存后返回同一份——
所以缓存适合 FAQ 类稳定内容,**聊天/创作类不要开**。生产换 Redis 等共享缓存,开了多个服务副本时,各副本才能读到同一份缓存。

### 2.2 重试与限流

```python
resilient = chain.with_retry(stop_after_attempt=3)      # 瞬时故障自动重试(第 4 章)

semaphore = BoundedSemaphore(3)                          # 全局同时最多 3 个请求
def rate_limited_invoke(chain, inp):
    with semaphore:
        return chain.invoke(inp)
```

限流保护的是**你自己的配额**:demo 用 8 并发请求、信号量闸门限到同时 3 个在飞。
供应商的 429(限流)不是异常而是常态,重试 + 限流是应对组合,缺一不可。
并发调用模型注意用**线程池/async**(LangChain 也有 `ainvoke/astream` 异步全家桶),
否则单线程串行,延迟相加。

## 3. Demo 10-1 · fastapi_service.py:HTTP 服务化

链/图都是 Runnable,套一层 Web 框架就是服务。三个端点:

```python
llm = get_llm()                          # 模块级单例:启动时创建一次,勿每请求新建

@app.post("/chat")                        # 普通接口:等完整答案
def chat(req: ChatRequest) -> dict: ...

@app.get("/chat/stream")                  # 流式接口:打字机效果
def chat_stream(question: str) -> StreamingResponse:
    def generate():
        for chunk in chain.stream({...}):
            yield chunk.content
    return StreamingResponse(generate(), media_type="text/plain; charset=utf-8")

@app.get("/health")                       # 探活:定期询问"服务还活着吗",负载均衡器(流量分发员)靠它判断
def health(): ...
```

运行与测试:

```bash
python -m demos.ch10_production.fastapi_service
# 浏览器打开 http://127.0.0.1:8000/docs 有交互式文档可点着试
curl "http://127.0.0.1:8000/chat/stream?question=一句话介绍智谱AI"
```

生产要点:

1. **多 worker**:`uvicorn demos.ch10_production.fastapi_service:app --workers 4`。
   worker 指"同时干活的程序副本"——开 4 个副本相当于 4 个服务员同时接客,吞吐更大。
   注意每个副本有自己独立的内存,所以共享缓存、会话历史必须放外部存储(Redis/DB),这也是第 5 章
   "记忆持久化"与本章的呼应;
2. **流式接口必须开 streaming 响应**(demo 已用 `StreamingResponse`),否则打字机效果退化为一次性返回;
3. **超时与降级**:给每个端点设置请求超时,失败时按第 4 章 fallback 返回兜底话术;
4. **鉴权**:demo 端点裸奔,生产加 API Key/OAuth,别把烧钱的接口暴露到公网。

## 4. 上线前的检查清单

把本教程全部章节串成一张"生产检查单":

- [ ] **密钥**:全部在 .env/密钥管理服务,代码与日志零泄漏(第 1 章)
- [ ] **确定性**:抽取/分类 temperature=0,关键路径有 schema 校验(第 3 章)
- [ ] **容错**:with_retry + fallback,超时必设(第 4 章)
- [ ] **记忆**:多会话隔离,历史裁剪或摘要,持久化到外部存储(第 5 章)
- [ ] **RAG**:检索有相关性过滤,答案可溯源,提示词有"仅根据资料"(第 6-7 章)
- [ ] **Agent**:工具白名单,危险操作加 human-in-the-loop,设 recursion_limit(第 8-9 章)
- [ ] **可观测**:LangSmith/替代方案接入,成本与错误率有看板(本章)
- [ ] **成本**:缓存开启(稳定内容),批处理走 batch,模型按需分档(贵活用旗舰,杂活用 flash)(本章)

## 5. 常见坑

1. **每请求新建模型客户端** —— 连接池浪费、握手变慢;模块级单例(demo 写法);
2. **开了缓存还期待随机性** —— 缓存命中返回同一份内容,创作类接口勿开;
3. **流式接口被中间件整段缓冲** —— 某些代理/中间件会攒齐再发,打字机失效,需关闭响应缓冲;
4. **无鉴权裸奔** —— AI 接口按 token 计费,公网裸奔=替别人买单;
5. **没有灰度** —— 提示词改动直接全量上线,翻车无回头路;提示词当配置管理,**灰度发布**(新版本先只放给一小部分用户试用,没问题再全量)+ 评估集回归。
