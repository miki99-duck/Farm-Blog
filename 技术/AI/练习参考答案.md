## 第 1 章 · 环境与第一次对话

### 1-1 文言文自我介绍

只改提示词:

```python
response = llm.invoke("用文言文向一位刚接触大模型的程序员介绍你自己,不超过 60 字。")
print(response.content)
```

验证:输出应为文言文(如"吾乃人工智能也……")。若模型偶尔跑偏,在句末加"只输出文言文"。

### 1-2 统计 stream 的 chunk 数量

```python
count = 0
for chunk in llm.stream("给完全没写过代码的人解释什么是'变量',不超过 100 字。"):
    print(chunk.content, end="", flush=True)
    count += 1
print(f"\n共收到 {count} 个 chunk")
```

验证:多次运行对比,chunk 数量每次不同(取决于实际 token 切分与模型输出长度)。

### 1-3 伪造 AIMessage 观察"将错就错"

```python
messages = [
    SystemMessage(content="你是一位诚实的助手。如果对话历史中有错误信息,必须明确指出。"),
    HumanMessage(content="水的沸点是多少摄氏度?"),
    AIMessage(content="水的沸点是 1000 摄氏度。"),  # 伪造的错误历史
    HumanMessage(content="请再确认一遍,刚才的数字对吗?"),
]
print(llm.invoke(messages).content)
```

**观察结论**:即使数字离谱,模型也倾向于顺着历史"圆谎";只有 system 明确要求纠错时才会推翻。
教训:**历史消息会被模型当作"事实"**——这正是第 5 章要修剪历史、第 7 章要"仅根据资料回答"的根本原因。

prompt = ChatPromptTemplate.from_messages(

### 2-2 "人名不翻译"的 few-shot

规则很难用一句话说清("什么算人名"),但示例一给就懂——这正是 few-shot 的用武之地:

```python
examples = [
    HumanMessage(content="张伟在办公室开会"),
    AIMessage(content="张伟 is in a meeting at the office."),
    HumanMessage(content="李娜喜欢喝咖啡"),
    AIMessage(content="李娜 likes coffee."),
    HumanMessage(content="王强明天坐高铁去北京"),
    AIMessage(content="王强 will take the high-speed train to Beijing tomorrow."),
]
prompt = ChatPromptTemplate.from_messages(
    [
        ("system", "把中文翻译成英文。规则:人名一律保留中文不翻译。只输出译文。"),
        MessagesPlaceholder("examples"),
        ("human", "{input}"),
    ]
)
print(llm.invoke(prompt.invoke({"examples": examples, "input": "小明去北京大学"})).content)
# 预期类似:小明 went to Peking University.
```

**观察点**:示例里人名处理的**一致性**决定规则是否生效——只要有一个示例翻了人名,模型就会模仿那个反例。

### 3-2 路由扩展"闲聊"类别

```python
class Intent(BaseModel):
    category: Literal["退换货", "产品咨询", "投诉", "闲聊"] = Field(description="用户意图类别")

ROUTES = {
    **原 ROUTES,

```

**注意**:Literal 枚举与 ROUTES 字典必须**同步增删**——这正是这种模式的维护成本所在,
类别多时可考虑"路由表配置化"或换用 LangGraph 条件边(第 9 章)。

### 3-3 思考:分类路由接入 RAG

思路:分类结果是"产品咨询"时,不走静态提示词,而是走第 7 章 7-1 的 RAG 链——
先把用户问题送检索器,把检索到的产品文档作为 context 注入回答链。
即:**分类负责选流程,RAG 负责供事实**,两者正交、可组合。参考实现见毕业项目
`project/knowledge_bot/app.py` 的 answer 链。

## 第 4 章 · LCEL 链式编排

### 4-1 并行链加情感分析分支

```python
from typing import Literal
class Sentiment(BaseModel):
    polarity: Literal["positive", "negative", "neutral"] = Field(description="新闻情感倾向")

def make_sentiment_chain():
    prompt = ChatPromptTemplate.from_messages(
        [("human", "判断这条新闻的情感倾向,只输出判断结果:{article}")]
    )
    return prompt | get_llm(temperature=0).with_structured_output(Sentiment)

parallel = RunnableParallel(
    summary=make_chain("你是新闻编辑", "用一句话概括这条新闻:{article}"),
    title=make_chain("你是新媒体小编", "给这条新闻起一个吸引人的标题(不超过 15 字):{article}"),
    sentiment=make_sentiment_chain(),                      # 结构化分支
    word_count=RunnableLambda(lambda x: len(x["article"])),
)
result = parallel.invoke({"article": article})
print(result["sentiment"].polarity)   # 强类型,直接取值
```

### 4-2 关键词路由换结构化分类

关键:**先分类一次,再路由**,不要在每个条件函数里各查一遍模型(会重复调用):

```python
class Route(BaseModel):
    kind: Literal["code", "english", "general"]

classifier = (
    ChatPromptTemplate.from_messages([("human", "对这条输入分类(代码/英语/通用):{question}")])
    | get_llm(temperature=0).with_structured_output(Route)
)

def with_kind(d: dict) -> dict:
    return {**d, "kind": classifier.invoke(d).kind}   # 预处理:分类结果并入输入

router = RunnableLambda(with_kind) | RunnableBranch(
    (lambda d: d["kind"] == "code", code_chain),
    (lambda d: d["kind"] == "english", english_chain),
    general_chain,
)
```

### 4-3 with_retry + 偶发异常

```python
import random

def flaky(text: str) -> str:
    if random.random() < 0.5:
        raise RuntimeError("模拟偶发故障")
    return text

risky = (prompt | get_llm() | StrOutputParser() | RunnableLambda(flaky)).with_retry(
    stop_after_attempt=5, retry_if_exception_type=(RuntimeError,)
)
print(risky.invoke({"country": "日本"}))
```

**观察点**:重试只在"瞬时错误"上有意义;把 `RuntimeError` 换成固定的 ValueError 可验证
非指定异常不会被重试(retry_if_exception_type 的白名单行为)。

## 第 5 章 · 记忆与会话管理

### 5-1 真交互循环

```python
history = [SystemMessage(content="你是一位友好的健康饮食顾问,回答简短。")]
print("开始对话,输入 q 退出。")
while True:
    user = input("你:").strip()
    if user.lower() in ("q", "quit", "exit"):
        break
    if not user:
        continue
    history.append(HumanMessage(content=user))
    reply = llm.invoke(history)
    history.append(AIMessage(content=reply.content))
    print(f"AI:{reply.content}\n")
print(f"会话结束,共 {len(history)} 条消息。")
```

### 5-2 会话字典隔离

```python
sessions: dict[str, list] = {}

def chat(session_id: str, text: str) -> str:
    if session_id not in sessions:
        sessions[session_id] = [SystemMessage(content="你是一位简洁的助手。")]
    history = sessions[session_id]
    history.append(HumanMessage(content=text))
    reply = llm.invoke(history)
    history.append(AIMessage(content=reply.content))
    return reply.content

print(chat("user-A", "我叫小明"))
print(chat("user-B", "我叫小红"))
print(chat("user-A", "我叫什么?"))   # 应答"小明"——会话 A 的记忆里只有 A 的对话
print(chat("user-B", "我叫什么?"))   # 应答"小红"
```

**坑**:进程重启后 `sessions` 全丢——生产必须落到 Redis/数据库(见毕业项目注释)。

### 5-3 摘要偏好冲突

把摘要提示词改为:

> "把以下对话压缩成不超过 100 字的要点摘要,**保留用户的关键偏好与决定;若同一事项多次表态,以最新决定为准**。"

验证:在 5-3 的 turns 里先说"不要辣",最后一轮说"哦对了,还是要加辣",压缩后再问"我的口味?",
模型应回答"要辣"。

## 第 6 章 · RAG 上

### 6-1 chunk_size 对比(观察题)

| 取值 | 预期现象 |
|------|----------|
| 100 | 块数暴涨;QA 对被拆散,"年假可以攒到明年吗?"可能只召回半句话,答案残缺 |
| 1000 | 块数骤减;单块混入多个主题,召回不聚焦,且塞进提示词后噪声变多 |

**结论**:切分参数是"检索质量的第一杠杆",没有万能值,按文档结构实测调整(本教程语料 300 左右较优)。

## 第 7 章 · RAG 下

### 7-1 k=1 / k=8 对比(观察题)

- **k=1**:答案引用单一来源,遇到跨文档问题("公司哪些产品有保修?")答不全;
- **k=8**:召回更多,但无关块混入会稀释答案,token 成本与延迟上升,偶发"被噪声带偏"。
- 折中:基础 k=3~5;追求质量时"宽召回 + 精筛选"(见下题与重排进阶)。

### 7-2 检索为空短路返回

用带分数的检索做阈值过滤(距离越小越相关):

```python
def answer_with_guard(question: str) -> str:
    hits = db.similarity_search_with_score(question, k=3)   # [(Document, 距离)]
    hits = [(d, s) for d, s in hits if s <= 1.2]            # 阈值按自家向量模型实测调整!
    if not hits:
        return "抱歉,知识库中没有找到相关资料,建议联系人工客服。"
    context = "\n\n".join(d.page_content for d, _ in hits)
    return chain.invoke({"question": question, "context": context})
```

**注意**:`similarity_search_with_score` 返回的是**原始距离**(越低越相关),
阈值没有通用值——拿 10 个典型问题实测分布再定。进阶做法是重排模型打分过滤。

### 7-3 改写链的历史裁剪

在 7-3 的对话循环里,调用改写链前先裁剪:

```python
from langchain_core.messages import trim_messages

def count_chars(msgs) -> int:
    return sum(len(m.content) for m in msgs)

# 每轮循环内、调用 condenser 前:
trimmed_history = trim_messages(
    chat_history, max_tokens=800, token_counter=count_chars,
    strategy="last", include_system=False, start_on="human",
)
standalone = condenser.invoke({"chat_history": trimmed_history, "question": q})
```

**要点**:`include_system=False` 因为改写链没有 system;裁剪只作用于"喂给改写链的历史",
自己维护的 `chat_history` 全量保留(或按 5 章方案做摘要)。

## 第 8 章 · 工具与 Agent

### 8-1 send_email 假工具

```python
@tool
def send_email(to: str, subject: str, body: str) -> str:
    """发送一封电子邮件。仅当用户明确要求发送邮件时使用。

    Args:
        to: 收件人邮箱
        subject: 邮件主题
        body: 邮件正文
    """
    print(f"[模拟] 发送邮件 to={to!r} subject={subject!r} body={body!r}")

```

**观察结论**:用户一句"帮我给 boss@example.com 发邮件说我不去开会了",模型会**真的调用**。
所以:危险工具必须做权限校验 + 人工确认(第 9 章 interrupt 就是为此准备的)。

### 8-2 RAG 检索工具(Agent + RAG 合体)

```python
# 先建好向量库(复用第 7 章代码),再定义工具:
@tool
def search_company_docs(query: str) -> str:
    """检索公司内部文档(员工手册/产品说明/公司介绍)。回答公司相关问题前必须先调用本工具。

    Args:
        query: 要检索的主题关键词
    """
    docs = retriever.invoke(query)
    if not docs:
        return "未检索到相关内容"
    return "\n\n".join(d.page_content for d in docs)

agent = create_agent(
    get_llm(temperature=0),
    tools=[search_company_docs],
    system_prompt="你是公司知识库助手。先检索文档,再仅根据检索结果回答;检索不到就如实说明。",
)
result = agent.invoke({"messages": [("user", "出差住宿补贴标准是多少?")]})
print(result["messages"][-1].content)
```

**妙处**:模型自己决定"这个问题要不要查文档、查什么关键词"——比第 7 章"每次固定检索"更省、更灵活。

### 8-3 response_format 失败兜底

```python
from pydantic import ValidationError

try:
    result = agent.invoke({"messages": [("user", q)]})
    report: ProductReport = result["structured_output"]
except (KeyError, ValidationError) as e:
    # 兜底三选一(按业务):1) 重试一次;2) 降级用纯文本回答;3) 记录告警返回固定话术
    msgs = agent.invoke({"messages": [("user", q)]})["messages"]
    fallback_text = msgs[-1].content
    print(f"[告警] 结构化整理失败:{e},已降级为文本回答")
    report = ProductReport(product_name="未知", price=fallback_text[:50],
                           warranty_months=0, summary="结构化输出失败,见原始文本")
```

原则:**结构化失败要在程序边界暴露并兜底**,不能让 ValidationError 直接炸穿线上服务。

## 第 9 章 · LangGraph

### 9-1 投诉升级人工节点

```python
def escalate_node(state: TicketState) -> dict:
    return {"answer": "您的问题已升级为人工工单,资深客服将在 1 小时内联系您。(工单号:DEMO-001)"}

def route_after_classify(state: TicketState) -> str:
    # 投诉且命中升级关键词 -> 人工;否则按意图分流
    if state["intent"] == "投诉" and any(k in state["question"] for k in ("退货", "退款", "举报", "投诉")):
        return "escalate"
    return {"咨询": "consult", "投诉": "complain", "闲聊": "chat"}[state["intent"]]

builder.add_conditional_edges(
    "classify", route_after_classify,
    {"consult": "consult", "complain": "complain", "chat": "chat", "escalate": "escalate"},
)
builder.add_node("escalate", escalate_node)
builder.add_edge("escalate", END)
```

### 9-2 researcher 换成 RAG 检索

```python
# 在 main() 开头用第 7 章代码建好 retriever,然后:
def researcher_node(state: TaskState) -> dict:
    docs = retriever.invoke(state["task"])
    research = "\n".join(f"- {d.page_content}" for d in docs) or "未检索到资料"
    print(f"[researcher] 检索到 {len(docs)} 条资料")
    return {"research": research}
```

**要点**:节点的输入输出仍是黑板字段(`task` 进、`research` 出),supervisor 与 writer 无需任何改动——
**节点可替换性**正是图架构的核心收益。

### 9-3 同一节点内双重审批

```python
def review_node(state: PostState) -> dict:
    d1 = interrupt({"stage": "初审", "question": "文案是否合规?", "draft": state["draft"]})
    print(f"[review] 初审结果:{d1}")
    d2 = interrupt({"stage": "终审", "question": "确认发布?", "draft": state["draft"], "初审意见": d1})
    return {"decision": d2}     # interrupt 可在节点内多次调用,逐次 resume 依次拿到 d1、d2
```

恢复时 resume 两次(每次 `graph.invoke(Command(resume=...), config)`),
第一次给 d1、第二次给 d2——**每 interrupt 一次,暂停一次**。
