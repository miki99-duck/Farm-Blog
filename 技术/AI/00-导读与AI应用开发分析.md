## 0. 开始之前:先搞懂三个最基础的名词

这三个词贯穿全书,先花两分钟弄懂,后面就不卡壳了。

### 大模型(LLM)

LLM 是 Large Language Model 的缩写,中文叫"大语言模型",俗称"大模型"。
你可以把它理解成**一个"读过海量文本、擅长接话的 AI 大脑"**——ChatGPT、智谱的 GLM 都属于这类。

它只做一件事:**读一段文字,回一段文字**。
你发给它的那段文字叫**提示词(prompt)**,其实就是"你对模型说的指令",
比如"帮我写一首关于秋天的诗"就是一条提示词。

### API 与 SDK:怎么"使用"一个大模型?

大模型运行在智谱、OpenAI 这样的公司服务器上,你电脑上并没有它。
你的程序要"用"它,就得隔着网络跟它打交道,这就引出两个词:

- **API**(应用程序接口):类比餐厅的**点菜窗口**——你的程序把请求("来一份翻译")递进窗口,
  模型服务把结果(翻译好的文字)递出来。你不需要知道后厨(模型)内部怎么运作。
- **SDK**(软件开发工具包):官方替你写好的**"点菜工具包"**。你不用自己研究窗口的规矩,
  安装后照着说明书调函数就能用。前文示例里的 `zhipuai` 就是智谱官方的 SDK。

### token:模型的"计费字块"

模型按 **token** 收费,也按 token 限制一次能处理的文字量。
token 可以理解为模型眼里的"字块":**大致相当于 1 个汉字**(英文更碎,半单词一块),
具体切法因模型而异,量级感受即可。

你发去的字 + 模型回的字,都算 token,都要花钱。
所以后文所有"省钱手段"(缓存、裁剪历史)本质上都是在省 token。

> 顺便记住:**上下文窗口(context window)** = 模型一次最多能"读进脑子"的文字量,也按 token 算。
> 类比书桌大小:桌子就这么大,超过桌面的资料它就读不了。主流模型的窗口从几万到几十万 token 不等。

好,三个地基名词齐了,开始正题。

## 1. 先摆正一个认知:大模型是"新式实习生",不是"新式函数"

写传统代码时,`abs(-3)` 永远返回 `3`,输出完全确定。而大模型的输出是**概率生成**的,它像一位特殊的实习生:

| 维度 | 传统代码 | 大模型 |
|------|----------|------------|
| 输出 | 确定的数据 | 自然语言,每次都可能不同 |
| 速度 | 毫秒级 | 秒级,说第一个字前要等一会儿 |
| 失败方式 | 明确报错 | **不报错,但可能一本正经地胡说**(行话叫"幻觉") |
| 成本 | 几乎为零 | 按 token 计费,用多少付多少 |
| 记忆 | 程序自己管 | **完全没有**,每次对话都"失忆" |

把大模型当成一位**知识渊博、但没有记忆、偶尔胡编、说话按字收费的实习生**来设计产品,
你就不会被它坑到。后面所有工程手段(让它填表、给它配记忆、开卷考试……)都是在对付这五条"脾气"。

> **幻觉(hallucination)**:模型编造不存在的信息,还说得言之凿凿。这是概率生成的天性,不是 bug,
> 只能靠工程手段(后面讲的"仅根据资料回答")来压制,无法根除。

## 2. 从"调一次接口"到"AI 产品",中间隔着什么?

最简单的 AI 应用就是调一次接口:

```python
# 裸调智谱官方 SDK,15 行,谁都会写
from zhipuai import ZhipuAI                 # 导入官方"点菜工具包"
client = ZhipuAI(api_key="...")             # 出示你的钥匙(API Key)
resp = client.chat.completions.create(      # 下单:发一条消息
    model="glm-4-flash",                    # 指定用哪个模型
    messages=[{"role": "user", "content": "你好"}],   # 用户说的话
)
print(resp.choices[0].message.content)      # 取出模型的回答
```

> **API Key(密钥)**:你在智谱官网注册后得到的一串"密码",证明"这个请求是你发的,费用记你账上"。
> 它就像银行卡密码——只能自己保管,绝不能写进代码发给别人(第 1 章教安全放法)。

但真实产品远不止于此。设想你要做一个"员工手册问答机器人",马上会撞上五个问题:

**痛点 1:模型没有记忆。**
用户问"年假几天",答完再问"那病假呢"——模型不知道"那"指的是什么,因为每次请求它都是失忆的。
你必须自己把历史对话每次都抄送给它;而对话越长,token 花得越多,还可能超出上下文窗口。
于是你需要一套**会话记忆管理**的办法(第 5 章)。

**痛点 2:模型不知道你的私有数据。**
模型的"知识"来自它训练时读过的公开文本,你公司的手册它根本没读过,直接问只会得到"幻觉"。
解决办法:把公司文档切成小块 → 给每块算出"语义坐标"存进**向量库**(第 6 章细讲)→
用户提问时找出最相关的几块,塞进提示词让模型"看着材料回答"。
这套流程叫 **RAG**(检索增强生成),类比**开卷考试**:不许凭记忆答,只能抄材料(第 6、7 章)。

**痛点 3:模型只会说话,不会做事。**
"帮我算一下 347 乘 892"、"查下现在几点"——模型算不准数字也没有时钟。
解决办法:把你写的函数登记成**工具(tool)**,模型遇到不会的事就"点菜"说"帮我调这个函数",
你执行后把结果告诉它,它再继续——这套循环就叫 **Agent(智能体)**(第 8 章)。

**痛点 4:流程一复杂,代码就散架。**
上面三件事叠加后,你的主程序里会混着:拼提示词的长字符串、解析文本的手工代码、
消息数组的增删改查、调用工具的循环……没有统一的"零件标准",每个环节都要手搓,而且换一家模型供应商很多东西要重写。

**痛点 5:没法观测、没法运维。**
线上用户说"机器人答错了",你却拿不到那次调用用了什么提示词、查了哪些资料、花了多少钱。
**可观测性**(给每次调用装"行车记录仪",第 10 章)在 AI 产品里是排障刚需,不是锦上添花。

一句话总结:**AI 产品的工程量,90% 不在"调模型",而在模型之外**。LangChain 就是把这些"模型之外"的部分标准化了。

## 3. LangChain 是什么:先懂"框架",再认"全家桶"

### 3.1 什么是"框架"?

**框架(framework)** = 别人预先搭好的"毛坯房带水电"。调用模型、管理记忆、检索文档……
这些每个 AI 产品都要的公共工程,框架已经铺好管线;你只负责放自己的家具(写业务逻辑)。

LangChain 就是 AI 应用领域最流行的框架。它自己**不提供模型能力**——模型还是智谱/OpenAI 家的,
LangChain 提供的是那套"统一的水电管线"。

### 3.2 全家桶成员(2026 · 1.0 时代)

```
        你的业务代码
             │
┌────────────▼──────────────────────────────────────────┐
│                  LangChain 生态                        │
│                                                       │
│   langchain      langgraph        langsmith           │
│   ┌────────┐    ┌─────────┐     ┌───────────┐         │
│   │现成的   │    │流程图引擎│     │监控后台    │         │
│   │好用人格 │    │(画流程用)│    │(网页版服务)│         │
│   └────┬───┘    └────┬────┘     └───────────┘         │
│        │  好用件建在流程图之上                           │
│   ┌────▼─────────────▼───────────────────────────┐    │
│   │     langchain-core(核心:零件的"插头标准")     │    │
│   └────┬──────────┬──────────┬───────────────────┘    │
│   ┌────▼───┐ ┌────▼────┐ ┌───▼─────────┐              │
│   │langchain│ │langchain│ │langchain-    │  …100+ 集成包 │
│   │-openai │ │-chroma  │ │-community    │              │
│   └────┬───┘ └────┬────┘ └───┬─────────┘              │
└────────┼──────────┼──────────┼────────────────────────┘
         ▼          ▼          ▼
      智谱 GLM    Chroma     其他任意模型/存储
    (模型服务)  (向量库)
```

逐个用白话过一遍:

| 包名 | 是什么(白话版) | 本教程哪章用 |
|------|----------------|------------|
| `langchain-core` | **零件的"插头标准"**:规定所有零件长同一种样子、能互相拼接 | 第 2 章起贯穿全程 |
| `langchain` | 用标准零件做好的**现成好物**,比如一行创建智能体的 `create_agent` | 第 8 章 |
| `langgraph` | **画流程图的引擎**:流程复杂(会拐弯、会回头、要等人)时用它 | 第 9 章 |
| `langchain-xxx` 集成包 | 对接具体厂商的**转接头**:`langchain-openai` 接模型,`langchain-chroma` 接向量库 | 第 1、6、7 章 |
| LangSmith | 官方的**监控后台**(网页服务),看每次调用的来龙去脉和花费 | 第 10 章(可选) |

> 上文说"插头标准"时的行话叫 **Runnable**(可运行的东西)和 **LCEL**(LangChain 的拼接语法)。
> 现在只需记住这个类比:LangChain 把所有零件做成**同一种插头**,所以能像积木一样随便拼。
> 第 4 章会用整整一章带你上手这套拼接术,到时候自然会懂。

### 3.3 一个必须知道的"接入技巧"

智谱 GLM 提供 **OpenAI 兼容端点**——意思是:智谱在自家服务器上"伪装"成了 OpenAI 的点菜窗口,
规矩一模一样。所以教程里统一用 `langchain-openai` 这个转接头,只改两个参数就接入国产模型:

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    model="glm-4-flash",                          # 智谱模型名
    api_key="你的智谱key",
    base_url="https://open.bigmodel.cn/api/paas/v4/",  # 关键:窗口地址指向智谱
)
```

- `base_url` 就是"点菜窗口的地址"。默认指向 OpenAI 官方,改一下就指向智谱。
- 这个写法学一次,DeepSeek、Qwen、Kimi 等"OpenAI 兼容"的模型全部同理——只换 `model` 和 `base_url`。
  这是国内做 AI 应用最实用的一项通用技能。

## 4. 版本须知:为什么网上旧教程不能照抄

LangChain 在 2023-2024 年(0.x 时代)以"链(chain)"为核心,API 改版极快,网上大量教程已过时。
**2025 年 10 月,LangChain 1.0 与 LangGraph 1.0 正式稳定**,官方承诺到 2.0 之前不再改接口
(版本号第一次位是 1.0,通常就意味着"接口稳定,可以放心学、放心用于生产")。本教程全部基于 1.0,
与旧教程的关键差异:

| 概念 | 0.x 旧写法(网上旧教程常见) | 1.0 现行写法(本教程) |
|------|------------------------------|------------------------|
| 智能体 | `AgentExecutor` + `initialize_agent` | **`create_agent`** |
| 对话记忆 | `ConversationChain` + `Memory` 类 | 手动管理消息历史 + 裁剪工具 |
| 链式拼接 | LCEL 管道 `prompt \| llm \| parser` | **保留,仍是最核心的写法** |
| 复杂流程 | 手写状态传递 | **LangGraph 流程图** |
| 预置智能体 | `create_react_agent`(langgraph.prebuilt) | `create_agent`(langchain.agents) |

看到 `AgentExecutor`、`ConversationBufferMemory`、`initialize_agent`,就可以判定那篇教程是旧版的:
读结论可以,抄代码不行。

## 5. 本教程的学习路线

三个台阶,由浅入深,每章"一篇讲解文档 + 2~4 个可独立运行的 demo":

```
第一阶 · 会用模型(第 1-4 章)          ← 所有应用的原子能力
   1 环境与第一次对话     装环境、发消息、流式输出
   2 Prompt 工程         把指令写成可复用的模板
   3 结构化输出           让模型按表格"填空"
   4 LCEL 链式编排        把零件串成流水线

第二阶 · 会做系统(第 5-7 章)          ← 大多数产品 = 这三样
   5 记忆与会话管理        让多轮对话接得上话
   6 RAG 上               文档切块、"语义坐标"、按意思检索
   7 RAG 下               组装出能溯源的问答系统

第三阶 · 会做智能体(第 8-10 章)       ← 前沿与生产化
   8 工具与 Agent         让模型调用你的函数
   9 LangGraph           流程图、多角色协作、人工把关
   10 生产化              监控、缓存、限流、做成网站服务
```

**前置要求**:最好会一点 Python(变量、函数、循环这些基本概念)。不会也别慌——
demo 代码注释都标了"哪里是什么、哪里可以改",跟着抄+改就能跑通;
代码里偶尔出现的 `x: str` 之类的**类型标注**,当作"这个参数应该传什么"的说明书来读即可。
不需要任何机器学习知识。

**准备物品**:一个智谱 API Key([免费申请](https://open.bigmodel.cn/usercenter/apikeys),
默认模型 `glm-4-flash` 是免费档,学完全套几乎零成本)。

**怎么学**:每章先读文档(10-15 分钟)→ 逐个运行 demo 并改一改(30 分钟)→ 做章末练习
(答案在[《练习参考答案》](练习参考答案.md))。demo 全部按规范写在 `demos/` 下,运行方式统一为:

```bash
python -m demos.ch01_quickstart.hello_llm
```

(`python -m` 的意思是"运行 Python 包里的某个文件",照抄即可;报错先检查是否在项目根目录下执行。)

## 6. 什么场景**不该**用 LangChain

分析要讲两面。以下情况直接用官方 SDK 更合适:

1. **单次调用、无流程**:就是一个"翻译接口",直接 SDK 十行搞定;
2. **强实时、极致性能**:框架的封装有一点点额外开销,超低延迟场景需自行评估;
3. **团队已有成熟的编排设施**:已有工作流引擎的团队,可以只借用核心的"插头标准"。

学习它的最大收益也不是"必须用它",而是**它把 AI 应用的标准问题域定义得很清楚**——
提示词、结构化输出、检索、工具、流程图、监控。就算最后不用 LangChain,这些问题在任何框架里都要解。
