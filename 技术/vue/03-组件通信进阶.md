# 第3章 组件通信进阶：插槽、provide/inject、ref、事件总线

> 一句话讲清：**props + $emit 管"父子直接对话"；本章是其余通信手段——
> 插槽（父往子里面"塞内容"）、provide/inject（跨层级传"上下文"）、
> ref（拿到子组件实例）、事件总线（非父子任意通信，慎用）。**
> Java/JS 对照：插槽 ≈ 模板方法模式里的"钩子位置"；provide/inject ≈ 依赖注入上下文；
> 事件总线 ≈ 全局事件中心（类似观察者）。

## 3.1 插槽 slot：父组件往子组件里"塞东西"

```vue
<!-- 子组件：Card.vue —— 留出可填空的区域 -->
<template>
  <div class="card">
    <div class="card__header">
      <slot name="title">卡片标题</slot>      <!-- 具名插槽：父可指定放哪 -->
    </div>
    <div class="card__body">
      <slot>默认内容</slot>                    <!-- 默认插槽：父塞的内容放这 -->
    </div>
    <div class="card__footer">
      <slot name="footer"></slot>
    </div>
  </div>
</template>
```

```vue
<!-- 父组件使用：往插槽里填内容 -->
<template>
  <Card>
    <!-- 默认插槽的内容 -->
    <p>设备 CR007 今天一切正常</p>

    <!-- 具名插槽：指定放在子组件的哪个 slot -->
    <template v-slot:title>设备总览</template>
    <!-- 简写：#title（v-slot 简写 #） -->
    <template #footer>
      <button @click="exportData">导出</button>
    </template>
  </Card>
</template>
```

为什么需要插槽：**复用布局、定制内容**——Card 的边框/背景/圆角是通用的，
里面的内容由使用方决定。Element UI 的 el-table 列、el-dialog 的内容全是插槽。

作用域插槽（进阶）：子组件把自己的数据传给插槽内容

```vue
<!-- 子：把 row 传出来 -->
<slot name="action" :row="row"></slot>

<!-- 父：接收并使用 -->
<template #action="{ row }">
  <el-button @click="edit(row)">编辑</el-button>
</template>
```

RuoYi 里典型：el-table 的自定义列就是这么干的（第7章详讲）。

## 3.2 provide / inject：跨层传"上下文"（不用逐层传 props）

```vue
<!-- 祖先组件（如 layout 布局）：提供 -->
<script>
export default {
  provide() {
    return {
      appName: '华润燃气平台',
      refreshDevice: this.refreshDevice    // 也可以提供方法
    }
  },
  methods: {
    refreshDevice() { ... }
  }
}
</script>

<!-- 深层子孙组件：直接注入使用，不用中间层一个个传 props -->
<script>
export default {
  inject: ['appName', 'refreshDevice'],
  created() {
    console.log(this.appName);     // '华润燃气平台'
    // this.refreshDevice()
  }
}
</script>
```

适用：主题、语言、全局配置、"由外层决定的内层能力"（如页面容器提供刷新控制）。
注意：provide/inject 的耦合是隐式的（不像 props 声明清楚），**适合"上下文"不适合业务数据传递**。

## 3.3 ref：直接拿到子组件实例（父子"越权"通道）

```vue
<!-- 父：引用子组件并调用它的方法 -->
<template>
  <DeviceForm ref="deviceForm" />
  <button @click="handleSubmit">提交</button>
</template>
<script>
export default {
  methods: {
    handleSubmit() {
      // 调用子组件暴露的方法/访问数据
      const valid = this.$refs.deviceForm.validateForm();
      if (valid) this.$refs.deviceForm.submit();
    }
  }
}
</script>
```

RuoYi 高频：表单组件（el-form）的校验方法就是靠 ref 调：

```js
this.$refs.form.validate(valid => {
  if (valid) { addDevice(this.form); ... }
});
```

注意点：ref 拿的是**组件实例**，能访问它的一切（打破封装），别滥用；
v-for 里的 ref 是数组（多个实例）。

## 3.4 事件总线：非父子通信（老项目常见，新代码慎用）

```js
// ① main.js 注册（Vue2 经典做法）
// Vue.prototype.$bus = new Vue()   // 利用 Vue 实例自带的事件系统

// ② 发布方：任何组件里发事件
this.$bus.$emit('device-updated', { id: 7 });

// ③ 订阅方：任何组件里监听
created() {
  this.$bus.$on('device-updated', this.handleUpdate);
},
beforeDestroy() {
  this.$bus.$off('device-updated', this.handleUpdate);   // 必须解绑！
}
```

为什么"慎用"（面试要能说出缺点）：
- 全局事件难追踪（不知道谁发的谁听的），排查困难；
- 忘记 $off 会内存泄漏和重复触发；
- 组件间隐式耦合。

现代替代方案：**状态管理 Vuex（第5章）**——数据共享走 store，数据流可追溯。
事件总线只适合"无状态的通知"（如"列表刷新一下"），且要严格配对 on/off。

## 3.5 通信方式总表（面试背这张表）

| 场景 | 手段 | 说明 |
|------|------|------|
| 父 → 子 | props | 单向数据流，最常见 |
| 子 → 父 | $emit | 事件+参数回传 |
| 父塞内容/定制子组件内部 | 具名插槽 + 作用域插槽 | 布局复用 |
| 跨多层上下文 | provide / inject | 全局能力/配置 |
| 父主动调子能力 | ref | 拿实例，破坏封装慎用 |
| 任意组件（非父子） | Vuex（首选）/ EventBus（慎用） | 全局共享状态走 Vuex |

## 3.6 常见坑快查

| 坑 | 现象 | 解法 |
|----|------|------|
| 插槽内容不显示 | slot 名字没对上 | 检查 name 与 v-slot 名一致 |
| 作用域插槽拿不到 row | 没在子组件传参 | `<slot :row="row">` 传出来 |
| provide 的是旧值 | 响应式丢失 | 提供函数或转 Vuex |
| ref 是 undefined | 子组件还没渲染 | mounted/nextTick 后取 |
| $bus 重复触发 | 忘了卸载 | beforeDestroy $off |
| v-for 里 ref 数组 | 直接调方法报错 | this.$refs.xxx[i] 遍历 |

## 3.7 面试自测

- Q：插槽是什么？具名插槽和默认插槽？★
  A：父向子组件指定位置塞内容；默认 <slot>、具名 <slot name="x"> 配 #x。
- Q：作用域插槽是什么？
  A：子组件把数据传给插槽内容（<slot :row="row">，父用 #name="{ row }"）。
- Q：provide/inject 和 props 区别？
  A：跨层级免逐层传；隐式耦合，适合上下文不适合业务数据。
- Q：ref 拿到的是什么？
  A：子组件实例或 DOM 元素，可调方法/读数据。
- Q：为什么 EventBus 不推荐？
  A：难追踪、易泄漏、隐式耦合；全局状态用 Vuex。

## 小结

- props+$emit 是主力：单向数据流清晰可预测。
- 插槽让"布局复用+内容自定义"；provide/inject 传上下文；ref 越权调用。
- 全局共享走 Vuex（第5章），EventBus 慎用配好 on/off。
- 面试就考一张表：什么场景用什么手段。
