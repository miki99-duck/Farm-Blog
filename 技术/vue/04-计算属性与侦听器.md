# 第4章 计算属性与侦听器（computed / watch 深水区）

> 一句话讲清：**computed = "根据已有数据派生新值"（有缓存、纯计算）；
> watch = "监听数据变化做副作用"（请求、保存、联动）；两者分工不同，选错就是又慢又乱。**
> Java/JS 对照：computed ≈ 缓存 getter（依赖不变不重算）；
> watch ≈ 属性变更监听器（类似 setter 里加钩子，但解耦）。

## 4.1 computed：声明式的派生值（首选）

```vue
<script>
export default {
  data() {
    return {
      devices: [
        { name: '调压器A', online: true, pressure: 12 },
        { name: '阀门B', online: false, pressure: 0 }
      ],
      keyword: ''
    }
  },
  computed: {
    // ① 派生统计：模板里直接用，不用 methods
    onlineCount() {
      return this.devices.filter(d => d.online).length;
    },
    // ② 筛选结果：keyword 变 → 自动重算 → 视图更新
    filteredDevices() {
      const kw = this.keyword.trim().toLowerCase();
      if (!kw) return this.devices;
      return this.devices.filter(d => d.name.toLowerCase().includes(kw));
    },
    // ③ 依赖多个数据
    summary() {
      return `${this.filteredDevices.length} 台 / 在线 ${this.onlineCount} 台`;
    }
  }
}
</script>
```

```vue
<template>
  <div>
    <input v-model="keyword" placeholder="搜索设备" />
    <p>{{ summary }}</p>
    <ul>
      <li v-for="d in filteredDevices" :key="d.name">{{ d.name }}</li>
    </ul>
  </div>
</template>
```

computed 的三大特性（面试必背）：
1. **缓存**：依赖不变，多次访问返回同一个结果（不重新计算）——性能；
2. **自动追踪依赖**：函数里用到的响应式数据都是依赖，任何一个变就重算；
3. **必须纯**：不产生副作用（不要发请求/不要改 data），否则缓存与副作用冲突。

### computed 与 methods 对比（第1章埋的，这里讲透）

```vue
<template>
  <p>{{ formatList() }}</p>      <!-- 每次渲染都重新执行 -->
  <p>{{ formattedList }}</p>     <!-- 依赖不变，只算一次 -->
</template>
```

引用 10 次 methods：执行 10 次；引用 10 次 computed：只算 1 次（依赖没变时）。

## 4.2 watch：命令式的副作用（请求、联动、持久化）

```vue
<script>
export default {
  data() {
    return {
      filter: { status: undefined, name: '' },
      pageNum: 1
    }
  },
  watch: {
    // ① 监听简单值：参数 (新值, 旧值)
    'filter.status'(newVal, oldVal) {
      console.log('状态筛选变化', oldVal, '→', newVal);
      this.pageNum = 1;          // 重置到第一页
      this.getList();            // 重新查（副作用）
    },
    // ② 监听对象属性（字符串路径写法）
    'filter.name'(val) {
      this.pageNum = 1;
      this.getList();
    },
    // ③ 深度监听：对象内部任意字段变都触发
    filter: {
      handler() {
        console.log('filter 内部变了');
        this.getList();
      },
      deep: true                // 递归监听内部（开销大，谨慎）
    },
    // ④ immediate：进入页面立刻执行一次（初始化就用 watch）
    pageNum: {
      handler() { this.getList(); },
      immediate: true           // 组件创建时就触发一次
    }
  },
  methods: {
    getList() { /* 请求列表 */ }
  }
}
</script>
```

watch 的正确使用姿势（面试讲法）：
- "某个数据变化后要**做事情**（请求/写存储/联动别的数据）→ watch"；
- "多个数据**派生**一个显示值 → computed"；
- **能用 computed 解决的不要用 watch**（computed 自动缓存+依赖追踪更高效）。

### watch 的性能坑（实战高频）

```js
// ❌ 把 computed 该干的事塞进 watch：手动管理派生状态，又多又杂
watch: {
  price() { this.total = this.price * this.count; },
  count() { this.total = this.price * this.count; }
}
// ✅ computed 一行搞定，还带缓存
computed: {
  total() { return this.price * this.count; }
}
```

### 深监听 vs 浅监听的细节（面试加分）

```js
// 浅监听（默认）：只有 this.filter 被整体替换才触发；内部字段改了不触发
filter(newVal) { ... }
// 深监听：内部任意变化都触发
filter: { handler() { ... }, deep: true }
// 代价：deep 要递归遍历遍历对象属性做依赖收集，对象大时性能差
// 优化：监听具体字段 'filter.status' 而不是整对象 deep
```

## 4.3 实战组合：搜索区（RuoYi 页面典型）

```vue
<template>
  <el-form :inline="true">
    <el-form-item>
      <el-input v-model="queryParams.deviceName" placeholder="设备名称"
                clearable @keyup.enter="handleQuery" />
    </el-form-item>
    <el-form-item>
      <el-select v-model="queryParams.status" placeholder="状态" clearable>
        <el-option label="在线" :value="1" />
        <el-option label="离线" :value="0" />
      </el-select>
    </el-form-item>
    <el-form-item>
      <el-button type="primary" @click="handleQuery">搜索</el-button>
      <el-button @click="resetQuery">重置</el-button>
    </el-form-item>
  </el-form>
</template>

<script>
export default {
  data() {
    return {
      queryParams: { pageNum: 1, pageSize: 10, deviceName: '', status: undefined },
      tableData: [],
      total: 0
    }
  },
  watch: {
    // 状态变化自动刷新（联动手感好）；名称搜索用回车/按钮显式触发
    'queryParams.status'(val) {
      this.queryParams.pageNum = 1;
      this.getList();
    }
  },
  methods: {
    getList() { /* listDevice(this.queryParams).then(...) */ },
    handleQuery() { this.queryParams.pageNum = 1; this.getList(); },
    resetQuery() {
      this.queryParams = { pageNum: 1, pageSize: 10, deviceName: '', status: undefined };
      this.getList();
    }
  }
}
</script>
```

要点：查询条件变化 → 重置页码 → 重新请求，是最常见的 watch/computed 联动场景。

## 4.4 常见坑快查

| 坑 | 现象 | 解法 |
|----|------|------|
| watch 不触发 | 监听对象内部属性没加 deep | 监听具体路径或 deep |
| watch 想初始化执行 | 首次不触发 | immediate: true |
| computed 里发请求 | 渲染卡/重复请求 | 挪到 watch 或方法 |
| 深监听性能差 | 大对象卡 | 监听具体路径（'a.b.c'） |
| computed 依赖另一个 computed | 忘写依赖 | 正常会自动追踪，写清即可 |
| watch 里改监听的值 | 死循环 | handler 里加条件判断 |

## 4.5 面试自测

- Q：computed 和 watch 选哪个？★
  A：派生显示值用 computed（缓存+纯）；数据变化触发副作用用 watch（请求/联动）。
- Q：computed 为什么有缓存？
  A：依赖收集（getter 被追踪），依赖没变直接返回缓存值。
- Q：watch 的 deep 和 immediate？★
  A：deep 深监听对象内部；immediate 创建时立即执行一次。
- Q：能只用 watch 不用 computed 吗？
  A：能，但手动、繁琐、易错；computed 是该场景的声明式正解。

## 小结

- computed：缓存 + 纯计算 + 自动依赖追踪——派生显示值首选。
- watch：副作用编排（请求/联动/持久化）；deep/immediate 两个开关。
- 实战套路：条件变化 → 重置页码 → 重新请求。
- 面试口诀：**"能 computed 不 watch，能 watch 不加 deep（用路径监听）"。**
