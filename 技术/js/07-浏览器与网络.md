# 第7章 浏览器与网络（Fetch / Axios / 同源策略）

> 一句话讲清：**浏览器里发 HTTP 请求的两条路——原生 fetch 和 axios 封装；
> 同源策略是浏览器安全底线，跨域由后端 CORS 或代理解决；
> RuoYi 的 request.js 就是 axios 的"统一出口"（拦截器+token+错误处理）。**
> Java 对照：fetch/axios ≈ RestTemplate/HttpClient；拦截器 ≈ Spring MVC 的
> HandlerInterceptor；跨域 ≈ 后端的 CORS 过滤器。

## 7.1 fetch：原生请求（现代 API）

```js
// 基本 GET
const res = await fetch('/api/devices?page=1&size=10');
const data = await res.json();      // 响应体解析 JSON

// 注意两个"反直觉"点（面试爱问）：
// ① fetch 只有网络错误才 reject；HTTP 404/500 不抛异常！
const res2 = await fetch('/api/xxx');
console.log(res2.ok);               // false（404/500 时）
// 要手动判断：
if (!res2.ok) throw new Error('请求失败: ' + res2.status);

// ② body 是流，只能读一次

// POST + JSON
const res3 = await fetch('/api/collect', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ deviceId: 7, value: 12.5 }),   // 必须序列化
});
```

## 7.2 axios：项目里的标准答案

RuoYi 用 axios（Vue2 时代标配），axios 相比 fetch 的几个增强：
- 请求/响应拦截器（统一加 token、统一处理错误码）；
- 自动 JSON 序列化/解析；
- 超时配置、取消请求；
- 浏览器兼容更好（老浏览器 Promise 支持不一致）。

```js
import axios from 'axios';

// 单独用
const { data } = await axios.get('/api/devices', { params: { page: 1 } });
const { data: created } = await axios.post('/api/collect', payload);
```

## 7.3 RuoYi 的 request.js 解剖（打开你的项目对照）

RuoYi 前端 `src/utils/request.js` 干的事（学它 = 学通用封装套路）：

```js
// 核心结构（概念版，与你项目一致）
const service = axios.create({
  baseURL: process.env.VUE_APP_BASE_API,   // 环境变量：开发代理/生产域名
  timeout: 30000,                          // 超时 30s
});

// 请求拦截器：统一加 token
service.interceptors.request.use(config => {
  const token = getToken();                // 从 cookie/store 拿 token
  if (token) config.headers.Authorization = 'Bearer ' + token;
  return config;
}, error => Promise.reject(error));

// 响应拦截器：统一解包 + 统一错误处理
service.interceptors.response.use(
  response => {
    const res = response.data;
    if (res.code === 200) return res;      // 业务成功才返回（后端约定 code）
    // 401：token 过期 → 踢回登录页
    if (res.code === 401) { logout(); location.reload(); }
    Message.error(res.msg);                // 统一弹错误
    return Promise.reject(res);
  },
  error => {                                // 网络/500 错误统一处理
    Message.error('系统繁忙');
    return Promise.reject(error);
  }
);

export default service;
```

业务层再包一层（`src/api/device.js` 风格）：

```js
// src/api/device.js —— 每个模块一个 api 文件
import request from '@/utils/request';

export function listDevice(query) {
  return request({ url: '/monitor/device/list', method: 'get', params: query });
}
export function addDevice(data) {
  return request({ url: '/monitor/device', method: 'post', data });
}
```

面试讲法："项目里所有请求走一个 axios 实例：请求拦截器加 token，
响应拦截器统一解业务码、401 踢登录、错误统一弹窗；业务代码只写 url 和参数。"

## 7.4 同源策略与跨域（面试重灾区）

同源定义：**协议 + 域名 + 端口 三者完全相同。**

```
http://localhost:8080  vs  http://localhost:8081   → 端口不同，跨域
http://localhost:8080  vs  https://localhost:8080  → 协议不同，跨域
http://a.com  vs  http://b.com                      → 域名不同，跨域
```

为什么限制：没有它，恶意网站可以悄悄调用你的已登录接口（CSRF 类攻击）。
浏览器**只限制"发出去读不回来"**——其实请求能发出，但响应被浏览器拦下。

解决跨域的三种主流方案：

```js
// 方案1：后端 CORS（标准、生产首选 —— 你后端 Spring 里加）
// Spring Boot:
@Configuration
public class CorsConfig implements WebMvcConfigurer {
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/**")
                .allowedOrigins("http://localhost:80")   // 别用 * 配凭证
                .allowedMethods("*")
                .allowedHeaders("*");
    }
}

// 方案2：开发环境代理（RuoYi 前端 vue.config.js 就是这套）
// 前端请求同源路径 → devServer 代理转发到后端
// devServer: {
//   proxy: { '/dev-api': { target: 'http://localhost:8080', changeOrigin: true } }
// }

// 方案3：JSONP（老古董，只剩历史意义；只支持 GET）
```

面试金句："**跨域是浏览器行为不是后端拒绝；生产用 CORS 白名单，开发用 devServer 代理，
带 cookie 的请求不能配 * 要精确 origin。**"

## 7.5 浏览器存储三兄弟（面试必考区别）

| 存储 | 大小 | 生命周期 | 场景 |
|------|------|---------|------|
| localStorage | ~5MB | 永久（手动清） | 用户偏好、主题、大而稳的数据 |
| sessionStorage | ~5MB | 标签页关闭即清 | 临时草稿、单页流程状态 |
| cookie | ~4KB | 可设过期；请求自动携带 | token 的存储载体、会话标识 |

```js
// localStorage 使用
localStorage.setItem('theme', 'dark');
localStorage.getItem('theme');     // "dark"
localStorage.removeItem('theme');

// cookie（RuoYi 的 Token 默认存 cookie，也可切 localStorage）
document.cookie = 'token=abc; path=/; max-age=604800';   // 7 天
```

安全提示（面试加分）：token 存 cookie 要配 HttpOnly（防止 JS 读取 → 防 XSS 偷 token）；
存 localStorage 防不了 XSS 但防 CSRF。这是"没有完美方案、看威胁模型"的经典话题。

## 7.6 缓存与加载性能：浏览器请求的隐形层

```js
// 浏览器缓存策略：
// - 强缓存：Cache-Control: max-age=3600（到期前不发请求）
// - 协商缓存：ETag/Last-Modified（每次问服务器"变了吗"，304 就复用）

// 发布新版本坑（RuoYi 常见）：页面改了用户还是旧的
// 解决：静态资源文件名带 hash（index.abc123.js），内容变 hash 变
// 后端接口：Cache-Control: no-cache 保证数据新鲜
```

面试讲法："前端静态资源用带 hash 的文件名 + 长缓存；接口数据不能强缓存
（no-cache + ETag），避免改了用户看不到新数据。"

## 7.7 常见坑快查

| 坑 | 现象 | 解法 |
|----|------|------|
| fetch 404 不报错 | 以为是 bug | 手动检查 res.ok |
| CORS 报错 | 前端配了也没用 | CORS 是后端/CORS 过滤器的事 |
| 请求发了两次 | 预检 OPTIONS | CORS 预检正常现象，后端允许即可 |
| token 没带上 | 401 | 检查请求拦截器/header 名 |
| 生产环境 404 | baseURL 不对 | 检查 VUE_APP_BASE_API 构建时注入 |
| 数据是旧的 | 浏览器缓存 | 接口 no-cache / 资源带 hash |

## 7.8 面试自测

- Q：fetch 和 axios 区别？★
  A：axios 基于 XHR 封装：拦截器、自动 JSON、超时统一；fetch 原生更底层需手写这些。
- Q：什么是同源？跨域怎么解决？★★
  A：协议+域名+端口；CORS（后端）、devServer 代理、JSONP（历史）。
- Q：localStorage/sessionStorage/cookie 区别？★
  A：大小、生命周期、是否自动携带到请求。
- Q：401 一般怎么处理？
  A：响应拦截器检测 → 清 token → 跳登录页。
- Q：token 存哪里安全？
  A：HttpOnly cookie 防 XSS 读取；localStorage 方便但 XSS 可偷；按威胁模型取舍。

## 小结

- 请求统一出口：axios 实例 + 拦截器（RuoYi request.js 就是范本）。
- 同源三要素：协议/域名/端口；跨域交后端 CORS 或代理。
- 存储三兄弟按生命周期和安全性选型。
- 面试主战场：同源策略、拦截器流程、存储区别。
