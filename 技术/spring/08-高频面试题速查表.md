## A. IoC / DI（8 题）

1. IoC 是什么？
   答：控制反转——对象的创建和依赖管理从代码里交出去，由容器统一负责。
   追问见第2章 2.1~2.2。

2. BeanFactory 和 ApplicationContext 的区别？★
   答：BeanFactory 是最底层容器（懒加载），ApplicationContext 是其子接口，
   增强事件/国际化/资源加载/AOP，启动时预创建单例。实际用的都是 ApplicationContext。

3. Bean 有哪几种作用域？
   答：singleton（默认）、prototype、request、session、application。
   prototype 每次 getBean 新对象，容器不管理它的销毁。

4. @Component / @Service / @Repository / @Controller 区别？
   答：功能完全相同（都是注册 Bean），只是语义分层（组件/业务/持久层/控制层）。
   @Configuration 特殊：会被 CGLIB 增强，保证 @Bean 单例。

5. @Autowired 和 @Resource 区别？★
   答：@Autowired 按类型（Spring 提供），歧义时 @Primary/@Qualifier 裁决；
   @Resource 按名称（JSR-250 标准），名字找不到再按类型。见第3章 3.2、3.4。

6. 三种注入方式选哪个？为什么？★
   答：优先构造器注入——依赖可 final、防循环依赖、易测试；
   setter 用于可选依赖；字段注入隐藏依赖、难测，避免。

7. 多个同类型 Bean 怎么注入？★
   答：@Primary 指定默认，@Qualifier 点名，或 List<Xxx> 注入全部按 @Order 排序。

8. BeanDefinition 是什么？
   答：Bean 的元数据"户口本"（类名/scope/init-method/属性值）。
   XML、@Component 扫描、@Bean 最终都变成 BeanDefinition。见第2章 2.3。

## B. Bean 生命周期（5 题）

9. Bean 生命周期完整流程？★
   答：实例化 → 属性填充（@Autowired）→ Aware 回调 → 初始化 → 可用 →
   容器关闭时销毁。代理在初始化后的 postProcessAfterInitialization 生成。

10. 初始化三件套顺序？★
    答：@PostConstruct → InitializingBean.afterPropertiesSet → init-method。
    销毁顺序：@PreDestroy → DisposableBean.destroy → destroy-method。

11. BeanPostProcessor 和 BeanFactoryPostProcessor 区别？★
    答：BFPP 在 Bean 实例化前执行、改 BeanDefinition；
    BPP 在 Bean 实例化过程中执行、改对象实例。先改户口本，再造人。

12. Aware 接口是干什么的？
    答：让 Bean 感知容器能力，如 BeanNameAware（知道自己的名字）、
    BeanFactoryAware（拿到容器）。回调顺序在属性填充之后、初始化之前。

13. 怎么在销毁时做清理？
    答：@PreDestroy 或实现 DisposableBean，或配置 destroy-method。
    注意 prototype Bean 的销毁容器不管，要自己处理。

## C. AOP（6 题）

14. AOP 解决什么问题？★
    答：把日志/事务/权限等横切逻辑从业务代码抽出来，动态代理织入，业务代码干净。

15. JDK 代理和 CGLIB 区别？★
    答：JDK 代理要求目标类有接口，生成实现同接口的代理；
    CGLIB 继承目标类生成子类，final 类/方法不行。Spring Boot 2.x 默认 CGLIB。

16. 代理在什么时候创建？★
    答：Bean 初始化完成后，AbstractAutoProxyCreator（BeanPostProcessor）的
    postProcessAfterInitialization，匹配到切面就生成代理替换原 Bean。

17. 同类内 this 调用为什么失效？怎么解决？★★
    答：this 是目标对象不是代理，切面拦不到。
    解决：注入自身代理 / AopContext.currentProxy() / 把方法拆到另一个 Bean。

18. 通知类型和执行顺序？
    答：@Around、@Before、@After、@AfterReturning、@AfterThrowing。
    正常路径：@Around前 → @Before → 方法 → @After → @Around后 → @AfterReturning。
    @After 类似 finally；多切面按 @Order 排序。

19. execution 表达式怎么写？
    答：execution(修饰符 返回类型 包.类.方法(参数))
    例：execution(* com.example.service.*.*(..)) = 任意返回值、service 包下所有方法。

## D. 事务（6 题）

20. @Transactional 原理？★
    答：AOP 切面（TransactionInterceptor）在方法前后开事务/提交/回滚，
    本质是拿到连接 setAutoCommit(false)，成功 commit、异常 rollback。

21. REQUIRED 和 REQUIRES_NEW 区别？★
    答：REQUIRED 加入外层事务同生共死；REQUIRES_NEW 挂起外层开新事务，
    独立提交回滚（典型：记日志不随业务回滚）。

22. 事务失效场景？（能说 4 个以上）★★
    答：自调用；异常被 try-catch 吞；检查异常没配 rollbackFor；
    非 public 方法；类没被 Spring 管理；final 方法；多线程；数据库引擎不支持；
    多数据源只管主源。详见第5章 5.4。

23. 为什么检查异常默认不回滚？
    答：检查异常是业务可恢复失败，框架不替你决定；RuntimeException 才回滚。
    要回滚检查异常用 @Transactional(rollbackFor = Exception.class)。

24. 多数据源事务怎么处理？★
    答：每个数据源配自己的事务管理器，@Transactional 默认只管 primary；
    跨源一致性需要 JTA（Atomikos）/Seata，或最终一致（本地消息表+重试）。

25. 隔离级别有哪几种？
    答：READ_UNCOMMITTED、READ_COMMITTED（Oracle 默认）、
    REPEATABLE_READ（MySQL 默认）、SERIALIZABLE。MySQL 靠 MVCC 基本避免幻读。

## E. 启动流程 / 自动装配（5 题）

26. refresh() 有哪些关键步骤？★
    答：核心三步：①invokeBeanFactoryPostProcessors（处理 @Configuration、
    生成 BeanDefinition）②registerBeanPostProcessors ③finishBeanFactoryInstantiation
    （实例化所有非懒加载单例）。详见第6章 6.2。

27. @SpringBootApplication 由哪几个注解组成？
    答：@SpringBootConfiguration（=@Configuration）+ @EnableAutoConfiguration + @ComponentScan。

28. 自动装配原理？★
    答：@EnableAutoConfiguration → @Import(AutoConfigurationImportSelector) →
    读 META-INF/spring/...AutoConfiguration.imports 清单 → 条件注解筛选 → 注册 Bean。

29. 常用条件注解有哪些？
    答：@ConditionalOnClass / @ConditionalOnMissingBean / @ConditionalOnProperty /
    @ConditionalOnBean / @ConditionalOnWebApplication。

30. 怎么覆盖自动配置的默认 Bean？★
    答：自定义同类型 @Bean（@ConditionalOnMissingBean 让位）；
    spring.autoconfigure.exclude；主类 exclude 属性。

## F. 虚拟线程与并发设计（7 题，对应第10~12章）

31. 虚拟线程是什么？和平台线程什么关系？★★
    答：JVM 用户态轻量级线程（Java 21 正式），M:N 模型——大量虚拟线程
    调度到少量载体线程（=CPU 核数）上；栈在堆上按需增长。

32. 虚拟线程为什么能提升吞吐？★
    答：阻塞点自动 unmount（让出载体线程），线程不再浪费在等待上；
    同时"等待中"的任务数量不再受线程数限制。**I/O 密集提升数量级，
    CPU 密集无提升**（并行度=核数）。

33. pinning 是什么？怎么避免？★
    答：synchronized 块内阻塞时虚拟线程无法卸载，载体线程被钉住。
    用 ReentrantLock（j.u.c 锁已改造为可让出）。

34. 虚拟线程下 ThreadLocal 有什么坑？
    答：海量虚拟线程各自持有 ThreadLocal → 内存放大；写载体线程的
    ThreadLocal 会串味。传递上下文用参数或 ScopedValue。

35. 虚拟线程下连接池怎么配？★
    答：用 Little's Law：连接数 ≈ 响应时间 × 吞吐；贴数据库真实吞吐而非并发；
    connection-timeout 必须显式设置（快速失败），监控 hikaricp_connections_pending。

36. 怎么限流？还是线程池吗？
    答：不是。虚拟线程下线程数不再是限流手段，改用 Semaphore 按下游限并发 +
    连接池边界 + 入口限流 + 队列削峰。

37. StructuredTaskScope 是什么？★
    答：结构化并发（Java 24 正式）：try-with-resources 的 scope 内 fork 子任务，
    scope 关闭必清理，失败统一传播并取消其余。配虚拟线程使用，防孤儿线程。

## G. Spring Security 7（3 题，对应第13章）

38. Security 的过滤器链有哪些关键环节？
    答：SecurityContext 恢复 → CSRF → 认证过滤器（表单/JWT/Bearer）→
    授权过滤器（AuthorizationFilter）。自己加的 JWT 过滤器插在认证环节前。

39. Security 5 → 7 的主要变化？★
    答：authorizeRequests → authorizeHttpRequests；antMatcher/mvcMatcher →
    requestMatchers；csrf().disable() → csrf(AbstractHttpConfigurer::disable)；
    继承 WebSecurityConfigurerAdapter → SecurityFilterChain @Bean + lambda DSL。

40. 无状态(JWT)服务怎么配 Security？
    答：sessionCreationPolicy(STATELESS) + 自定义 token 过滤器塞
    SecurityContext + 关闭 CSRF（无 Cookie 天然免疫）+ 401/403 处理器。

## H. Spring AI（2 题，对应第14章）

41. Spring AI 是什么？★
    答：官方 LLM 开发框架，统一 API 换厂商（OpenAI 兼容即可接 DeepSeek/通义），
    ChatClient 像 JdbcTemplate，PromptTemplate 像 SQL。

42. RAG 原理？★
    答：检索增强生成两步：① 用户问题向量化 → 向量库找相关知识片段
    （语义相似度，优于关键词）② 把"问题+片段"一起给大模型，基于片段回答。
    Spring AI 里一行 Advisor 完成：QuestionAnswerAdvisor。
