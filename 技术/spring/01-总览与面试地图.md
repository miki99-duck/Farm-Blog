## 1.2 Spring 全家桶：一张图看懂

Spring 不是"一个框架"，而是一套分层的技术体系。面试官问"你对 Spring 的理解"，其实在考察你对这张图的认知边界。

```
┌─────────────────────────────────────────────────────┐
│                Spring Boot（自动装配 + 起步依赖）        │  ← 简化配置，约定优于配置
├─────────────────────────────────────────────────────┤
│   Spring Web MVC / WebFlux         Spring Security   │  ← Web 与安全
├─────────────────────────────────────────────────────┤
│   Spring Data (JPA/Redis/Mongo)   Spring Cloud (微服务)│
├─────────────────────────────────────────────────────┤
│   Spring AOP（切面）      Spring TX（事务）             │  ← 横切能力，面试重灾区
├─────────────────────────────────────────────────────┤
│   Spring Core：IoC 容器（BeanFactory / ApplicationContext）│  ← 地基，一切之上
├─────────────────────────────────────────────────────┤
│   Spring Framework（核心）                           │
└─────────────────────────────────────────────────────┘
```

要点：**IoC 容器是地基，AOP/事务建立在容器之上，Spring Boot 是包装层**。
面试时按"底层能力 → 横切能力 → 自动装配"三层讲，比平铺罗列全家桶高一个段位。

## 1.3 三大核心概念的一句话定义

| 概念 | 一句话讲清（背这个） |
|------|----------------------|
| IoC（控制反转） | 对象的创建和依赖关系从"由代码 new 出来"反转给"容器管理"，程序员只声明"我要什么"，不关心"怎么造" |
| DI（依赖注入） | IoC 的实现方式：容器在创建 Bean 时，把它的依赖对象"送进来"，而不是 Bean 自己去 new |
| AOP（面向切面） | 把日志、事务、权限这类"横切逻辑"从业务代码中抽出来，通过动态代理在方法执行前后织入，业务代码保持干净 |

一句话串联：**IoC 是思想，DI 是手段，AOP 是容器基础上的横切能力。**

## 1.5 结合简历项目（华润 IoT 平台）

- 你的项目是 Spring Boot 2.7 + RuoYi-Vue，IotPersistenceService 批量落库、多数据源（MySQL/PostgreSQL/Oracle）。
- 面试讲原理时主动挂钩：多数据源事务边界 → 引到第5章"@Transactional 默认只管主数据源"；
  Kafka 消费幂等 → 引到"方法级事务与消费重试"；MyBatis 的 Mapper 注入 → 引到第3章 @Autowired 处理。
- 原则：**每个原理讲完，补一句"我在项目里是这么用的/这里踩过坑"**，比空背原理强得多。
