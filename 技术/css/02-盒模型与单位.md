# 第2章 盒模型与单位

> 一句话讲清：页面上每个元素都是一只"盒子"——**内容(content) → 内边距(padding) →
> 边框(border) → 外边距(margin)**。所有布局问题都从盒子里长出来。
> 后端类比：盒子 ≈ 一个 DTO，width/height 是它的字段，box-sizing 是它的"尺寸计算策略"。

## 2.1 盒子长什么样

```
┌──────────────────────────────┐  ← margin（外边距：不与目标盒内元素重叠，透明区域）
│  ┌────────────────────────┐  │  ← border（边框）
│  │  ┌──────────────────┐  │  │  ← padding（内边距：内容与边框之间的"呼吸空间"）
│  │  │    content       │  │  │
│  │  │   内容区          │  │  │
│  │  └──────────────────┘  │  │
│  └────────────────────────┘  │
└──────────────────────────────┘
```

```css
.box {
  width: 200px;        /* 内容区宽度 */
  padding: 10px;       /* 四个方向内边距 */
  border: 1px solid #ddd;
  margin: 16px;        /* 四个方向外边距 */
}
```

问题立刻来了：**这个盒子的总宽是多少？**——取决于 box-sizing。

## 2.2 box-sizing：旧时代最大陷阱

```css
/* 默认值：content-box —— width 只算内容区，padding/border 另加 */
.box { width: 200px; padding: 10px; border: 1px solid; }
/* 总宽 = 200 + 20 + 2 = 222px。布局时永远算不准！ */

/* 推荐：border-box —— width 包含 padding 和 border */
* { box-sizing: border-box; }
.box { width: 200px; padding: 10px; border: 1px solid; }
/* 总宽 = 200px（内容区自动缩为 178px）。写多少就是多少。 */
```

为什么全网都要 `* { box-sizing: border-box; }`：
- 布局按"元素占用的总宽"思考，而不是"内容宽"，心智负担减半。
- **百分比/栅格布局不炸**：`.col { width: 33.33%; padding: 10px; }` 在 content-box 下
  三列会超宽换行，border-box 下完美三等分（RuoYi 和 Element UI 全局都是 border-box）。

面试口径："盒模型有两种，content-box 算宽不含 padding，border-box 算总宽；
现代项目一律 border-box，因为布局可预测。"

## 2.3 margin：布局的"弹簧"

margin 的四个高频用法：

```css
/* ① 水平居中（对块级元素，且父级够宽） */
.center { margin: 0 auto; }

/* ② 垂直居中三件套之一（配合 flex，见第3章） */
/* ③ 间距：兄弟元素之间的间距用 margin */
.btn + .btn { margin-left: 8px; }        /* 按钮组间距 */

/* ④ 负 margin（偶尔用来纠偏，少用） */
.nav { margin-top: -20px; }              /* 上提 20px */
```

### 必考坑 1：margin 塌陷（Collapsing Margins）

**垂直方向上，相邻的 margin 会合并取大值**，而不是相加：

```html
<div class="a">A</div>   <!-- margin-bottom: 30px -->
<div class="b">B</div>   <!-- margin-top: 20px -->
```
```css
.a { margin-bottom: 30px; }
.b { margin-top: 20px; }
/* A/B 之间的间距 = 30px（不是 50px！） */
```

同理：父元素第一个子元素的 margin-top 会"穿透"到父元素外面：

```css
.parent { background: #eee; }
.child { margin-top: 20px; }   /* 父元素没有 padding/border 时，这 20px 会把父元素也顶下去 */
```

解决三板斧（面试背）：父元素加 `padding-top`/`border-top`，或化 `overflow: hidden`，
或者干脆**用 flex/grid 布局（内部不塌陷）**——现代方案推荐最后一个。

### 必考坑 2：margin 不合并的水平场景

左右 margin 永远相加：`.left {margin-right:10px} .right {margin-left:10px}` → 间距 20px。
**只有垂直方向塌陷**，这是 CSS 历史遗留（当年排版基于文字行）。

## 2.4 padding vs margin：怎么选

简单决策：**元素内部空间用 padding，元素与外部之间的间距用 margin。**

```css
/* 正确示例：按钮文字离边框近一点 → padding */
.btn { padding: 8px 16px; }

/* 错误示例：不想让按钮贴边 → 给按钮加 margin 而不是塞 padding 到每个父级 */
```

经验：间距问题先想 margin；"内容顶住边框/背景"想 padding。

## 2.5 单位：px / rem / em / % / vw/vh

| 单位 | 含义 | 适用 |
|------|------|------|
| px | 物理像素的 1/96 英寸（CSS 像素） | 边框、细线、固定尺寸 |
| **rem** | 根元素字体大小的倍数（默认 16px → 1rem=16px） | **一切可缩放尺寸的首选** |
| em | 当前元素字体大小的倍数 | 跟随字号变化的场景 |
| % | 相对父元素（宽高/字体/行高语义不同） | 栅格、响应式 |
| vw/vh | 视口宽/高的 1% | 全屏、大区块 |
| ch | 字符 "0" 的宽度 | 等宽文本容器 |

为什么"长宽高用 rem、1px 用 px"：
- rem 跟随根字号 → 响应式做**字体缩放适配**时，全局按比例放大/缩小只需改 html 根字号；
- px 用于边框这种"不该缩放"的东西。

```css
/* RuoYi 常见做法：根字号统一主题尺寸 */
:root { font-size: 14px; }            /* 项目基准 */
.box { width: 20rem; }                /* = 280px，随根字号缩放 */
.border-1 { border: 1px solid #ddd; } /* 边框固定 1px */
```

em 的坑（面试爱问）：em 是"当前元素的 font-size 倍数"，**嵌套时会叠加放大**：

```css
.parent { font-size: 1.2em; }  /* 相对父：1.2 倍 */
.child  { font-size: 1.2em; }  /* 相对 .parent：又 1.2 倍 → 总共 1.44 倍！ */
```
嵌套越深字越大——这是老项目里"字越套越大"的元凶。**嵌套场景用 rem 代替 em**。

## 2.6 CSS 变量：后端的"配置中心"

CSS 变量（自定义属性）是现代 CSS 的配置抽象，面试高频：

```css
/* ① 定义：在 :root 上定义全局变量（RuoYi/Element 的主题色就是这么来的） */
:root {
  --primary-color: #409eff;
  --success-color: #67c23a;
  --text-main: #333;
  --radius: 4px;
}

/* ② 使用：var() 取值 */
.btn {
  background: var(--primary-color);
  border-radius: var(--radius);
}
.btn--success {
  background: var(--success-color);   /* 换肤只需改变量 */
}

/* ③ 局部覆盖：变量有作用域，子树里改、只影响子树 */
.dark-theme {
  --primary-color: #7c5cff;           /* 只在这个容器内生效 */
}
.dark-theme .btn { /* 自动变紫，不用重写按钮样式 */ }
```

后端类比：:root 变量 ≈ application.yml 的公共配置；局部覆盖 ≈ 环境变量 per-profile。

与 SCSS 变量的区别（面试可能问）：
- CSS 变量**运行时可改**（JS 改、媒体查询里改、hover 改）→ 动态换肤全靠它；
- SCSS 变量编译期就定死，不能运行时改。

```js
// JS 动态改主题色（CSS 变量的杀手锏）
document.documentElement.style.setProperty('--primary-color', '#ff6600');
```

## 2.7 高度问题：为什么 height 经常失效

```css
.child { height: 50%; }   /* 50% 是相对父级的“内容高度” */
```
如果父级的高度是"由内容撑开"（未显式设置 height），那 50% 就无从计算 → 失效/塌陷。

结论：**百分比高度链需要一路显式设置**（html/body/父级都有 height），
否则就是"无源之水"。这也是为什么现代布局高度多用 flex 的 stretch 撑开，而不是 height:100%。

宽度相反：块级元素默认 width: auto = 填满父级内容宽，所以 `width: 100%` 很少是必要的。

## 2.8 面试自测

- Q：content-box 和 border-box 差在哪？
  A：width 是否包含 padding/border；现代项目用 border-box 保布局可预测。
- Q：margin 塌陷是什么？怎么避免？
  A：垂直相邻 margin 合并取大；避免=flex/grid 布局、父级加 padding/border/overflow。
- Q：rem 和 em 区别？
  A：rem 相对根字号，em 相对当前字号；嵌套 em 会叠加放大，布局用 rem。
- Q：CSS 变量和 SCSS 变量区别？
  A：CSS 变量运行时可变（JS/媒体查询），SCSS 变量编译期定死。

## 小结

- 盒子 = content + padding + border + margin，总宽由 box-sizing 决定，一律 border-box。
- 垂直 margin 塌陷是高频坑，flex/grid 可绕开。
- 单位口诀：长宽高 rem、边框 px、栅格 %、视口大块用 vw/vh。
- CSS 变量 = 运行时可配置的主题系统，动态换肤首选。
