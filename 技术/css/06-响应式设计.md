# 第6章 响应式设计

> 一句话讲清：**同一个页面，在手机、平板、桌面自动呈现合适的布局——
> 手法是"弹性单位 + 弹性布局 + 断点微调"，核心心态是"从窄到宽渐进增强"。**
> RuoYi 是典型的"桌面优先"系统，但登录页/移动端也需要响应式兜底；
> 面试问响应式：答得上"移动优先 + 断点策略 + 弹性单位"就是完整答案。

## 6.1 三条腿：没有哪条能单独撑起响应式

```
① 弹性变形：百分比 / fr / rem / vw（内容随容器伸缩）
② 弹性布局：flex / grid（自动换行、自动加列）
③ 断点切换：媒体查询（在特定宽度下换规则）
```

正确认知：**先让①②把页面"弹性"起来，媒体查询只做"结构性转折"**——
不是每个尺寸写一遍，而是"窄屏一套默认，宽屏才加规则"。

## 6.2 移动优先（Mobile First）与断点策略

```css
/* 默认：先写手机版（窄屏优先，代码最少最基础） */
.card-list { display: grid; grid-template-columns: 1fr; gap: 12px; }

/* ≥768px：平板两列 */
@media (min-width: 768px) {
  .card-list { grid-template-columns: repeat(2, 1fr); }
}

/* ≥1200px：桌面四列 */
@media (min-width: 1200px) {
  .card-list { grid-template-columns: repeat(4, 1fr); }
}
```

为什么移动优先：手机是"最小约束"，先满足最苛刻的环境，再用 min-width 逐步增强，
比 max-width（从大往小缩）逻辑更顺——**每一条 min-width 都是"更强设备的额外能力"。**

三种断点写法对比：

```css
@media (min-width: 900px) { }   /* ≥900：移动优先，推荐 */
@media (max-width: 899px) { }   /* <900：桌面优先（RuoYi 常见） */
@media (min-width: 700px) and (max-width: 900px) { }  /* 区间：精确但啰嗦 */
```

面试补充：现代 Responsive 也可以用容器查询 @container（第9章细讲），
但媒体查询仍是基础必答。

## 6.3 弹性单位：让尺寸跟着环境走

```css
/* 字体：整体缩放用 rem（改根字号即可全局缩放） */
:root { font-size: 14px; }
@media (min-width: 1200px) {
  :root { font-size: 16px; }   /* 大屏字大一点：一行代码全局放大 */
}

/* 大区块：视口单位 */
.hero { height: 60vh; }           /* 首屏 60% 视口高 */

/* 布局间距：flex grid gap 本身就是弹性 */
.card-list { gap: clamp(12px, 2vw, 24px); }  /* 12~24px 之间随视口平滑变化 */
```

clamp() 的妙用（面试加分）：`clamp(最小值, 首选值, 最大值)`——平滑缩放，免断点：

```css
/* 标题字号：手机16px → 桌面32px，中间平滑过渡，无跳变 */
h1 { font-size: clamp(16px, 4vw, 32px); }
```

## 6.4 布局的响应式三件套

### ① grid 自动列（第4章的 auto-fill + minmax，响应式主力）

```css
.grid { grid-template-columns: repeat(auto-fit, minmax(260px, 1fr)); }
```
手机 1 列、平板 2 列、桌面 4 列，**零媒体查询**。

### ② flex 换行

```css
.toolbar { display: flex; flex-wrap: wrap; gap: 8px; }
```
按钮组在窄屏自动换行，不会挤出屏幕。

### ③ 上下→左右（结构性转折，才用媒体查询）

```css
@media (min-width: 768px) {
  .profile { display: flex; }   /* 手机：头像上文字下；平板后可左右 */
}
```

## 6.5 图片/媒体：别让它们撑破容器

```css
/* 万能配方：图片宽度不超容器，高度自适应 */
img, video {
  max-width: 100%;
  height: auto;
}

/* 背景图：cover 保持比例铺满 */
.banner { background-size: cover; background-position: center; }
```

## 6.6 触控优化：移动端必须做的最小改动

```css
/* ① 输入框不自动缩放（手机 Safari/Chrome 会默认放大聚焦的输入框） */
input, select, textarea { font-size: 16px; }  /* ≥16px 就禁止自动缩放 */

/* ② 点击目标最小 44px（Apple HIG 建议） */
.btn { min-height: 44px; }

/* ③ 去掉点击高亮 */
a, button { -webkit-tap-highlight-color: transparent; }
```

## 6.7 RuoYi 场景实战：登录页响应式改造思路

RuoYi 登录页是桌面版为主。改造思路（示例）：

```css
/* 默认（手机）：卡片全宽、表单竖排、logo 缩小 */
.login-card {
  width: 100%;
  max-width: 420px;      /* 手机也不会全无边界 */
  padding: 24px;
}

/* 桌面：恢复呼吸感 */
@media (min-width: 992px) {
  .login-card { padding: 40px; }
  .login-form .el-form-item { margin-bottom: 28px; }
}
```

配套必做：`<meta name="viewport" content="width=device-width, initial-scale=1">`
——没有它，手机浏览器会按 980px 宽渲染页面再等比缩小，你的响应式全部白费。

## 6.8 常见坑快查

| 坑 | 现象 | 解决 |
|----|------|------|
| 手机显示"缩成一页" | 缺 viewport meta | 必须加 viewport meta |
| 字号用 px 写死 | 大屏/小屏都难受 | 标题 clamp()，正文 rem |
| 图片撑爆宽度 | 图片超过容器 | max-width: 100% |
| 断点越写越多 | 每个尺寸都加规则 | 先弹性布局，只在结构转折处写断点 |
| 桌面优先改移动 | max-width 规则混乱 | 统一成 min-width 移动优先 |

## 6.9 面试自测

- Q：响应式三件套是什么？
  A：弹性单位（rem/vw/%）、弹性布局（flex/grid）、断点媒体查询。
- Q：移动优先怎么写断点？
  A：默认窄屏样式 + @media (min-width: 断点) 逐步增强。
- Q：clamp() 干什么用？
  A：一个区间内平滑缩放，min(下限, 首选 vw, 上限)，减少断点。
- Q：图片怎么防溢出？
  A：max-width: 100%; height: auto。
- Q：为什么移动优先？
  A：手机是最小约束，先满足苛刻环境，加 min-width 增强逻辑顺、代码少。

## 小结

- 弹性单位 + 弹性布局打底，媒体查询只在结构转折处出手。
- 移动优先：默认窄屏，min-width 增强。
- clamp / auto-fit / flex-wrap 是三个"免断点"神器。
- 记牢 viewport meta，否则一切白搭。
