# 第5章 定位与层叠上下文

> 一句话讲清：**position 决定元素"参照谁、以什么方式"摆放；z-index 决定重叠时谁在上面。
> 但 z-index 只在对的"层叠上下文"里起作用——这是面试最爱挖的坑。**
> 后端类比：position 大约等于"依赖注入的来源"；z-index 大约等于节点路由的优先级。

## 5.1 position 五兄弟

| 值 | 参照物 | 特点 | 典型场景 |
|----|--------|------|----------|
| static | 无（默认） | 占文档流，top/left 无效 | 大多数普通元素 |
| relative | 自身原来的位置 | 占位保留，可偏移；**常作定位锚点** | 图标微调、给 absolute 当父级 |
| absolute | 最近的 positioned 祖先（有 position 的） | 脱离文档流，不占位 | 弹层、角标、悬浮按钮 |
| fixed | 视口（屏幕） | 脱离文档流，滚动不动 | 顶部导航、回到顶部按钮 |
| sticky | 滚动容器 | 先随流，滚到阈值后"吸住" | 表头吸顶、侧栏跟随 |

### 关键理解：absolute 的"参照父级"

absolute 不是相对于页面（那是 fixed），而是**向上找最近的一个带 position 的祖先**。
这就是"relative 定位锚点"经典模式的由来：

```html
<div class="card">                    <!-- position: relative（锚点） -->
  <span class="badge">NEW</span>      <!-- position: absolute → 相对 .card 定位 -->
</div>
```

```css
.card { position: relative; }                       /* 锚点：让后代 absolute 以我为参照 */
.badge {
  position: absolute;
  top: -6px; right: -6px;                          /* 右上角徽标 */
  background: #f56c6c; color: #fff;
  border-radius: 50%; padding: 2px 6px;
}
```

没有锚点时 absolute 会一路找到 body（视口），所以**给 absolute 元素的父级加
position: relative 是标配习惯**。

### sticky 速记

```css
.sticky-header {
  position: sticky;
  top: 0;              /* 滚动到距顶部 0 时吸住 */
}
```
要点：sticky 只在"滚动容器内"生效，且父容器不结束时它会跟着走。

## 5.2 z-index：只管"同上下文"之间的顺序

```css
.a { position: absolute; z-index: 10; }
.b { position: absolute; z-index: 5; }
/* a 在上面 */
```

z-index 只在**同一层叠上下文**内比较。什么会创建层叠上下文？

- position + z-index（非 auto）→ 最常见
- transform、opacity < 1、filter、will-change
- display: flex/grid 的子项且 z-index 非 auto
- position: fixed

面试经典题：为什么明明 z-index: 9999 还是被压住？

```html
<div class="parent1">  <!-- transform: translateZ(0) → 创建了层叠上下文 -->
  <div class="popup" style="z-index: 9999"></div>  <!-- 只能在 parent1 内部称王 -->
</div>
<div class="parent2">  <!-- 普通 -->
  <div class="overlay" style="z-index: 1"></div>
</div>
```

答案：popup 的 9999 是"家长"parent1 上下文里的排名；跨上下文比的是**家长之间**的
层级（parent1 没设 z-index/级别低于 parent2 的 overlay 的层级？取决于父级本身），
所以 popup 永远盖不住 overlay。**结论：先看两个元素的"上下文祖先"谁高，再看组内 z-index。**

一句口诀：**"z-index 是小组内排名，跨组先比组。"**

## 5.3 层叠的完整顺序（含背景与内容）

同一上下文内，从底到顶：

```
1. 背景与边框（最底）
2. 负 z-index 元素
3. 块级元素（文档流）
4. 浮动元素
5. 行内元素（文字）
6. z-index: auto/0 的定位元素（按文档顺序）
7. 正 z-index 元素（按数值）
```

不必背全，记住"背景 < 负z < 块 < 浮 < 行内 < 定位元素"的大致梯队即可，
实际开发 99% 情况只争 z-index 数值和顺序。

## 5.4 BFC：看不见的"结界"（高频概念）

BFC（Block Formatting Context，块级格式化上下文）是一块**独立渲染的区域**。
创建 BFC 的方式（面试背这几种）：

```css
/* ① overflow 不为 visible */
overflow: hidden;
/* ② display: flow-root（现代、无副作用，推荐） */
display: flow-root;
/* ③ flex/grid 容器本身 */
display: flex;
/* ④ position: absolute / fixed */
/* ⑤ float（历史方案） */
```

BFC 的三大作用（都靠"独立结界"实现）：

```css
/* ① 治 margin 塌陷：父亲和儿子的 margin 不穿透 */
.parent { display: flow-root; }

/* ② 含浮动：父容器不会因为子 float 塌成 0 高 */
.parent { display: flow-root; }
.child  { float: left; }   /* 父容器依然包住子元素 */

/* ③ 防文字环绕：侧边栏 float，正文 BFC 后不环绕不吃亏 */
.aside  { float: left; width: 200px; }
.content { display: flow-root; }   /* 与浮动的 aside 隔离开 */
```

面试讲法："BFC 是一个独立的布局结界，常见用途是解决 margin 塌陷、包裹浮动、
隔离文本环绕；现代推荐 display: flow-root 创建。"

## 5.5 常见坑快查

| 坑 | 现象 | 解决 |
|----|------|------|
| absolute 不到预期位置 | 父级没设 position | 给父级 relative |
| z-index 大却压不住 | 祖先创建了层叠上下文 | 排查祖先的 transform/z-index/fixed |
| fixed 失效/相对错了 | 祖先有 transform/filter | fixed 会被"拉入"祖先的包含块，去掉 transform |
| sticky 不吸顶 | 父容器太矮/没有滚动容器 | 确保父容器有高度且有滚动，top 生效 |
| 弹层被裁切 | overflow: hidden 祖先 | 弹层放到 body 层渲染（Vue 的 Teleport） |

## 5.6 实战：下拉菜单（absolute + hover）

```css
.menu-item { position: relative; }
.dropdown {
  position: absolute;
  top: 100%; left: 0;          /* 挂在按钮正下方 */
  display: none;               /* 先隐藏 */
  min-width: 120px;
  border: 1px solid #eee;
  background: #fff;
  box-shadow: 0 4px 12px rgba(0,0,0,.1);
}
.menu-item:hover .dropdown { display: block; }  /* hover 显示 */
```

要点：absolute 相对 menu-item（锚点），top: 100% = 父级底部，left: 0 对齐父级左缘。

## 5.7 面试自测

- Q：absolute 相对谁定位？
  A：最近的带 position（非 static）的祖先；没有就一路到根（body/viewport）。
- Q：z-index 为什么不生效？
  A：先在 DOM 链上找两个元素各自的"层叠上下文祖先"，比祖先的层级；同级再比 z-index。
- Q：BFC 是什么？怎么创建？
  A：独立渲染结界；overflow:hidden、display:flow-root、flex/grid 容器、absolute/fixed 等。
- Q：BFC 三大作用？
  A：防 margin 塌陷、包裹浮动、隔离文字环绕。

## 小结

- relative 是锚点，absolute 找锚点，fixed 盯视口，sticky 吸顶。
- z-index 是"小组内排名"，跨组先比组——transform/fixed/opacity 都会造"组"。
- BFC 结界三用：塌陷、包裹浮动、隔离环绕，用 flow-root 创建。
- 弹层问题先查是不是被层叠上下文或 overflow 困住了。
