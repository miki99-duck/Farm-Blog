# 第10章 性能优化与面试速查(全书收尾)

> 一句话讲清:**3D 性能瓶颈只有三个——绘制调用太多、顶点太多、每帧计算太多;
> 优化顺序也是三个——先砍绘制调用、再减顶点、最后减计算。**
> 本章目标:掌握性能监控手段 + 三大优化手段 + 全书高频面试题 30 分钟速刷。

## 10.1 先量化:怎么知道卡不卡

```js
// 1. 帧率(FPS):60 理想,30 可接受,<25 要优化
// 每 60 帧统计一次耗时
let frames = 0, lastTime = performance.now();
function tick() {
  frames++;
  if (performance.now() - lastTime >= 1000) {
    const fps = frames;
    console.log('FPS:', fps);
    frames = 0;
    lastTime = performance.now();
  }
  renderer.render(scene, camera);
  requestAnimationFrame(tick);
}

// 2. 绘制调用次数:直接读 renderer 的属性(最核心指标!)
console.log(renderer.info.render.calls);    // 每帧多少次绘制调用
console.log(renderer.info.render.triangles); // 每帧多少三角形
console.log(renderer.info.memory.geometries); // 几何体数量
```

**面试必背:性能三个指标 = 帧率(FPS) / 绘制调用(Draw Calls) / 三角形数(Triangles)。**
优化的本质就是:让 FPS 回来——降低调用数、降低三角形数。

## 10.2 优化一:减少绘制调用(效果最明显)

**绘制调用 = 每帧 CPU 提交给 GPU 的"画一个物体"命令。物体越多调用越多,CPU 越忙。**

```js
// ❌ 1000 个设备各自画 → 1000 次调用
// ✅ 方案1:几何体合并(Geometry Merge)——静态物体合成一个

// 把 1000 个球体合并成一个几何体,一次调用画完
import { mergeGeometries } from 'three/addons/utils/BufferGeometryUtils.js';

const geos = [];
devices.forEach((dev) => {
  const geo = new THREE.SphereGeometry(0.5, 16, 12);
  geo.translate(dev.x, 1.2, dev.z);   // ★ 先平移到各自位置,再合并
  geos.push(geo);
});
const merged = mergeGeometries(geos);  // 合成一个几何体(1000 个球的所有顶点)
const material = new THREE.MeshBasicMaterial({ color: 0x00aaff });
const allDevices = new THREE.Mesh(merged, material);
scene.add(allDevices);                 // 1 次调用!

// ✅ 方案2:实例化(InstancedMesh)——大量相同物体,还能单独控制每个
const count = 1000;
const instanced = new THREE.InstancedMesh(
  new THREE.SphereGeometry(0.5, 16, 12),
  new THREE.MeshBasicMaterial({ color: 0x00aaff }),
  count
);
const dummy = new THREE.Object3D();
devices.forEach((dev, i) => {
  dummy.position.set(dev.x, 1.2, dev.z);
  dummy.updateMatrix();
  instanced.setMatrixAt(i, dummy.matrix);   // 每个实例的位置矩阵
});
scene.add(instanced);   // 1 次调用,还能 per-instance 改颜色
```

| 方案 | 适合 | 特点 |
|------|------|------|
| 合并几何体 mergeGeometries | 静态物体(地面/围栏/背景) | 合并后不能再单独动 |
| InstancedMesh | 大量相同物体(设备/树/路灯) | 可单独控制每个实例位置/颜色 |
| Points | 粒子 | 最省调用 |

**面试必答:合并 vs 实例化的区别?**
合并:把多个几何体揉成一个,之后"整体"一个对象,不能单独控制;
实例化:一次绘制但保留每个实例的独立矩阵,可以单独改位置/颜色/缩放——**设备点位用 InstancedMesh 最合适。**

## 10.3 优化二:减少顶点数(几何体瘦身)

```js
// 1. 分段数够用就行(第2章提过)
// ❌ SphereGeometry(1, 64, 64)   → 4096 顶点/球
// ✅ SphereGeometry(1, 16, 12)   → 192 顶点/球(视觉差异极小,性能 20 倍)

// 2. 用模型代替几何体堆细节
// 贴图(normalMap)模拟细节,别真的建凸起

// 3. LOD(Level of Detail):距离远用低模,近才用高模
import { LOD } from 'three';

const lod = new LOD();
lod.addLevel(highDetailMesh, 0);    // 距离 < 10:高模
lod.addLevel(midDetailMesh, 10);    // 10~30:中模
lod.addLevel(lowDetailMesh, 30);    // >30:低模
scene.add(lod);
// LOD 每帧自动根据"相机到物体的距离"切换层级 —— 远处省顶点,近处保质量
```

**面试考点:LOD 原理?** 按相机距离给物体换不同精度的模型——远处人眼分辨不出细节,
用低模(少顶点),近处才切高模。大屏"整个厂区"用 LOD 非常有效。

## 10.4 优化三:减少每帧计算

```js
// 1. 相机裁剪:设置合理的 near/far(第3章),远处物体自动不渲染
// 2. 只渲染可见区域:renderer 默认就做,别手动把物体移到看不见的地方还留着
// 3. 限制光源数量(第4章):每加一个光源,所有受光材质都要多算一遍光照
// 4. 关闭不必要的效果:
renderer.shadowMap.enabled = false;          // 阴影很贵,大屏能不开就不开
renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));  // 高分屏限制像素比(3 倍像素没意义)
// 5. 动画只算需要动的(第9章):告警设备才算 sin,别让 1000 个物体每帧都算
// 6. 粒子和特效用 Basic 材质(第8章):不受光,省光照计算
```

**高频坑:setPixelRatio 不设,高分屏(2x/3x)画面会非常卡** —— 像素数是 4 倍/9 倍。
`Math.min(devicePixelRatio, 2)` 是标配。

## 10.5 内存管理:dispose(防内存泄漏)

```js
// 场景销毁/刷新时,必须手动释放 GPU 资源(JS 的 GC 管不了 GPU 内存)
function disposeObject(obj) {
  obj.geometry?.dispose();        // 释放几何体(顶点缓冲)
  obj.material?.dispose();        // 释放材质(着色器/纹理)
  if (obj.material.map) obj.material.map.dispose();  // 释放纹理图片
}

// 大屏"切换页面/刷新数据"时:
scene.traverse((obj) => {          // 遍历场景所有对象
  if (obj.isMesh || obj.isPoints || obj.isLine) disposeObject(obj);
});
renderer.dispose();                // 最后释放渲染器
```

**面试考点:为什么要 dispose?** Three.js 创建的几何体/材质会占用 GPU 显存,
JS 垃圾回收管不到 GPU 资源。不 dispose,反复刷新页面会显存泄漏、越来越卡。

## 10.6 全书高频面试题速查(30 分钟刷完)

### 原理类(5 题)

**Q1:WebGL 和 Three.js 的关系?**
答:"WebGL 是浏览器原生 3D API,Three.js 是对象化封装,内部自动管着色器/矩阵/渲染状态。"
扩展:"WebGL 底层画三角形要写着色器、管 buffer;Three.js 一行 BoxGeometry 搞定。"

**Q2:场景三要素?**
答:"Scene(舞台)+ Camera(眼睛)+ Renderer(画布)。Scene 装物体,相机定视角,渲染器输出到 canvas。"

**Q3:渲染为什么是循环?**
答:"场景动态,每帧状态可能变,必须每帧重画;用 requestAnimationFrame 由浏览器在重绘前调用。"

**Q4:坐标系?**
答:"右手系:x 右、y 上、z 朝屏幕外;角度单位弧度,Math.PI = 180 度。"

**Q5:透视 vs 正交相机?**
答:"透视近大远小像人眼(fov/aspect/near/far);正交无透视像工程图(left/right/top/bottom/near/far)。"

### 材质与光(5 题)

**Q6:材质怎么选?**
答:"真实感 Standard、哑光 Lambert、光泽 Phong、调试 Basic/Normal、性能 Matcap。"

**Q7:为什么 Basic 不受光?**
答:"它直接把颜色输出到像素,不做光照计算——永远亮,适合 UI/特效/调试。"

**Q8:物体全黑怎么排查?**
答:"1 查有没有光源(Standard 无光=黑);2 查强度;3 查光源位置是否在背面。"

**Q9:阴影四条件?**
答:"渲染器 shadowMap.enabled + 光源 castShadow + 物体 castShadow + 接收面 receiveShadow。"

**Q10:环境光有方向吗?**
答:"没有,均匀加色、不产生明暗阴影,只保底可见。立体感靠平行/点/聚光。"

### 交互与动画(5 题)

**Q11:3D 点击拾取原理?**
答:"屏幕坐标转 NDC → Raycaster 从相机发射线 → intersectObjects 求交,最近交点即目标。"

**Q12:为什么动画用 delta 不用固定增量?**
答:"帧率不固定,固定增量在 144Hz 屏会快一倍;delta 是真实时间差,任何设备速度一致。"

**Q13:getDelta vs getElapsedTime?**
答:"delta 增量管速度(自转/移动);elapsed 累计管波形(正弦弹跳/圆周公转)。"

**Q14:告警闪烁怎么做?**
答:"emissiveIntensity 随时间正弦变化 + 红色 emissive;只有告警设备参与,省性能。"

**Q15:TWEEN 是什么?**
答:"补间库:起点→终点→时长自动插值,带缓动函数;相机切换/位置过渡用它。"

### 性能(5 题)

**Q16:卡顿先查什么?**
答:"三指标:FPS(目标 60)、绘制调用次数(renderer.info.render.calls)、三角形数。"

**Q17:怎么减少绘制调用?**
答:"合并几何体(静态)、InstancedMesh(大量相同物体)、Points(粒子);从 1000 次降到 1 次。"

**Q18:合并 vs 实例化区别?**
答:"合并后不能单独控制;InstancedMesh 保留每实例矩阵,能单独改位置/颜色/缩放。"

**Q19:LOD 是什么?**
答:"按相机距离切换高低模:远处低模省顶点,近处高模保质量,大场景必备。"

**Q20:为什么页面反复刷新越来越卡?**
答:"GPU 资源没释放——geometry/material/texture 要手动 dispose,JS GC 管不到显存。"

### 大屏专项(5 题)

**Q21:3D 大屏怎么分层?**
答:"HTML 覆盖层管图表/数字,3D 管空间与状态可视化;能用 HTML 画的别用 3D。"

**Q22:设备点位怎么数据驱动?**
答:"后端返回 JSON 数组 → 遍历生成点位;刷新时增量更新颜色/动画,不重建场景。"

**Q23:点设备看数据链路?**
答:"Raycaster 拾取 → userData.id → fetch 详情 → 信息面板。"

**Q24:数据刷新轮询还是 WebSocket?**
答:"批量状态用轮询(5s+),告警事件用 WebSocket 秒级推送,可组合。"

**Q25:大屏特效性能铁律?**
答:"特效 Basic 材质、粒子 Points + depthWrite:false + AdditiveBlending、光源 1~2 个、限制 pixelRatio。"

### 高频坑(5 题)

**Q26:相机在原点看不到物体?**
答:"和物体重叠,移开 + lookAt;near 太大/far 太小也会看不见。"

**Q27:透明不生效?**
答:"transparent: true 是开关,必须和 opacity 成对;PNG 要有 alpha 通道。"

**Q28:点了没反应/点不准?**
答:"NDC y 要反转(-(clientY/height)*2+1);检测前 setFromCamera;只传可交互数组。"

**Q29:粒子闪成一片?**
答:"depthWrite: false;配合圆形贴图 alphaTest + AdditiveBlending。"

**Q30:画面发白/发灰?**
答:"AmbientLight 太高(≤0.6),补 DirectionalLight 制造明暗对比。"
