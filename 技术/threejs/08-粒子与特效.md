# 第8章 粒子与特效:大屏的"科技感"

> 一句话讲清:**粒子系统(Points)是"成千上万个点"的批量渲染——一个几何体存所有点的位置,
> GPU 一次画完,所以几千个点也不卡;大屏的星空/飞线/辉光全是这套思路。**
> 本章目标:掌握 Points 粒子、飞线、呼吸光圈三种大屏特效,理解"批量渲染"的性能本质。

## 8.1 原理:为什么粒子"多而不卡"?

**普通 Mesh:一个物体一次渲染调用(draw call),1000 个 Mesh = 1000 次调用,卡。
粒子(Points):把 1000 个点的位置放进"一个"几何体,一次调用画完,快。**

```js
// 对比:5000 个球 vs 5000 个粒子点
// ❌ 5000 个 Sphere Mesh → 5000 次绘制调用,直接卡死
// ✅ 5000 个粒子点(Points) → 1 次绘制调用,丝滑
```

**面试核心:绘制调用(Draw Call)是什么?** 每次 GPU 渲染一个物体(绑定状态+提交顶点)就是一次调用,
调用次数过多 CPU 就忙不过来(GPU 空闲等待)。粒子把大量顶点合并到一次调用里,
所以"点很多但调用很少"——这是大屏不卡的底层原理(第10章还会讲合批)。

## 8.2 星空粒子:Points 最小示例(★ 必跑通)

```html
<script type="importmap">
  { "imports": {
      "three": "https://cdn.jsdelivr.net/npm/three@0.160.0/build/three.module.js",
      "three/addons/": "https://cdn.jsdelivr.net/npm/three@0.160.0/examples/jsm/"
  } }
</script>
<script type="module">
  import * as THREE from 'three';

  const scene = new THREE.Scene();
  const camera = new THREE.PerspectiveCamera(75, window.innerWidth / window.innerHeight, 0.1, 1000);
  camera.position.z = 5;
  const renderer = new THREE.WebGLRenderer();
  renderer.setSize(window.innerWidth, window.innerHeight);
  document.body.appendChild(renderer.domElement);

  // 1. 生成 5000 个随机点的位置(一个 Float32Array)
  const count = 5000;
  const positions = new Float32Array(count * 3);   // 每点 x,y,z 三个值
  for (let i = 0; i < count * 3; i++) {
    positions[i] = (Math.random() - 0.5) * 50;     // -25 ~ 25 随机分布
  }

  // 2. 把位置数据交给 BufferGeometry
  const geometry = new THREE.BufferGeometry();
  geometry.setAttribute('position',
    new THREE.BufferAttribute(positions, 3));      // 3 个一组 = 一个点

  // 3. 粒子材质(点的大小/颜色)
  const material = new THREE.PointsMaterial({
    color: 0xffffff,
    size: 0.1,             // 点的大小(世界单位)
    sizeAttenuation: true, // 远近缩放(近大远小,更真实)
  });

  // 4. Points 对象(不是 Mesh!没有几何体表面,只有点)
  const stars = new THREE.Points(geometry, material);
  scene.add(stars);

  function animate() {
    requestAnimationFrame(animate);
    stars.rotation.y += 0.001;   // 整个星云慢慢转
    renderer.render(scene, camera);
  }
  animate();
</script>
```

**Points 与 Mesh 的区别(面试小考点):**

| | Mesh | Points |
|--|------|--------|
| 画什么 | 三角面(有体积) | 一个个点(无体积) |
| 数据结构 | 顶点 + 索引 + 法线 | 只需要 position 顶点 |
| 用途 | 实体物体 | 粒子/星空/点位/飞线 |

## 8.3 粒子大小与纹理:圆形粒子(避免方块点)

```js
// 默认 PointsMaterial 的点是"方块"。想圆润:用一张圆形渐变图做贴图
const texture = new THREE.TextureLoader().load('https://threejs.org/examples/textures/sprites/circle.png');

const material = new THREE.PointsMaterial({
  color: 0x00aaff,
  size: 0.3,
  map: texture,             // ★ 圆形贴图
  transparent: true,
  alphaTest: 0.5,           // 丢弃方块角落的透明像素
  depthWrite: false,        // 粒子不写深度缓冲,防止互相遮挡闪烁(高频坑)
  blending: THREE.AdditiveBlending,  // 叠加混合:亮色相加,越叠越亮(发光感)
});
```

**depthWrite: false 为什么重要?** 粒子是"点",如果写深度缓冲,后面的粒子会被前面的挡住/闪烁。
关闭后粒子像"光点"一样叠加,配合 AdditiveBlending 有发光效果。**大屏粒子三件套:
map(圆形图) + depthWrite:false + AdditiveBlending。**

## 8.4 飞线:设备之间的数据流动(大屏经典)

飞线 = 用曲线把 A 点连到 B 点,再让一个"亮点"沿曲线移动。

```js
// 1. 画曲线(贝塞尔:起点/终点/控制点)
const start = new THREE.Vector3(0, 1, 0);
const end = new THREE.Vector3(4, 1, 3);
const mid = new THREE.Vector3(2, 4, 1.5);          // 控制点抬高,形成弧线

const curve = new THREE.QuadraticBezierCurve3(start, mid, end);

// 2. 生成曲线上的点 → 管状/线条
const points = curve.getPoints(50);                // 曲线采样 50 个点
const lineGeo = new THREE.BufferGeometry().setFromPoints(points);
const line = new THREE.Line(
  lineGeo,
  new THREE.LineBasicMaterial({ color: 0x00aaff, transparent: true, opacity: 0.5 })
);
scene.add(line);

// 3. 移动的"光点":沿曲线移动(第6章的 Clock 驱动)
const dot = new THREE.Mesh(
  new THREE.SphereGeometry(0.1, 8, 8),
  new THREE.MeshBasicMaterial({ color: 0x00ffff })
);
scene.add(dot);

const clock = new THREE.Clock();
function animate() {
  requestAnimationFrame(animate);
  const t = clock.getElapsedTime() % 1;            // 0~1 循环
  dot.position.copy(curve.getPointAt(t));          // ★ 曲线上 t 位置的点
  renderer.render(scene, camera);
}
animate();
```

**曲线 API 一句话:** `curve.getPointAt(t)` 返回曲线上"按长度比例 t(0~1)"的位置点——
光点每帧取不同 t,就沿曲线匀速飞。**大屏数据流转动画就是这条线 + 光点 + 业务数据绑定。**

## 8.5 呼吸光圈:设备位置强调(告警/选中)

```js
// 设备脚下放一个"呼吸光圈":圆环贴图 + 缩放/透明度变化
function createRing(color = 0x00aaff) {
  const tex = new THREE.TextureLoader().load('https://threejs.org/examples/textures/sprites/circle.png');
  const ring = new THREE.Mesh(
    new THREE.PlaneGeometry(1, 1),
    new THREE.MeshBasicMaterial({
      map: tex, color, transparent: true, depthWrite: false,
      blending: THREE.AdditiveBlending,
    })
  );
  ring.rotation.x = -Math.PI / 2;    // 躺平
  ring.position.y = 0.02;            // 贴地
  return ring;
}

// 动画:缩放 + 淡出(典型的"扩散波")
function animateRing(ring, clock) {
  const t = (clock.getElapsedTime() * 2) % 1;   // 0~1 循环
  ring.scale.set(1 + t * 3, 1 + t * 3, 1);      // 越扩散越大
  ring.material.opacity = 1 - t;                // 越扩散越淡
}
```

## 8.6 大屏特效组合套路(直接抄)

```js
// 完整大屏底子:星空背景 + 地面网格 + 光圈 + 飞线
// 1. 星空:8.2 的 Points(背景氛围)
// 2. 地面:GridHelper + 半透明 Plane(参考系)
// 3. 设备:球体/模型 + 脚下呼吸光圈(8.5)
// 4. 数据流:飞线连接设备对(8.4)
// 5. 重点:告警设备红色光圈 + 闪烁(第6章)
// 性能铁律:特效都用 Basic 材质(不受光),光源只保留 1~2 个
```

**大屏特效性能三条铁律(面试可答):**

1. **特效材质用 MeshBasicMaterial**(不受光,省光照计算)。
2. **能用 Points 不用 Mesh**(合并绘制调用)。
3. **粒子关 depthWrite + 开 AdditiveBlending**(视觉对 + 省排序)。

## 8.7 常见坑汇总

| # | 坑 | 现象 | 解决 |
|---|----|------|------|
| 1 | 粒子互相遮挡闪烁 | 粒子闪成一片 | `depthWrite: false` |
| 2 | 粒子是方块 | 科技感变"马赛克" | 圆形贴图 + alphaTest |
| 3 | 点太大/太小 | 看不见或糊一脸 | 调 `size`,注意 `sizeAttenuation` 远近缩放 |
| 4 | 飞线光点乱跳 | 位置不连续 | 用 `getPointAt(t)`(按弧长),别用 `getPoint(t)`(按参数,弧长不等) |
| 5 | 光圈穿模 | 光圈陷进地面 | position.y 抬高一点(0.01~0.05) |
| 6 | 粒子太亮 | 白花花一片 | 降 size、降数量、颜色调暗 |
| 7 | 5000 个 Mesh 当粒子 | 卡成 PPT | 用 Points,不是 Mesh |

## 8.8 面试自测(追问链)

**Q1:为什么粒子用 Points 而不是很多小 Mesh?**
一句话:"Points 把所有顶点放一个几何体,一次绘制调用画完;很多 Mesh 是多次绘制调用,CPU 忙不过来。"
追问:绘制调用是什么?(GPU 每次渲染一个对象的状态切换+提交,调用多了成瓶颈)

**Q2:粒子闪烁怎么解决?**
一句话:"depthWrite: false——粒子不写深度缓冲,就不会互相遮挡闪烁;配合 AdditiveBlending 更亮。"
追问:为什么关深度没问题?(粒子是半透明光点,视觉上应该叠加而不是遮挡)

**Q3:飞线动画怎么做?**
一句话:"贝塞尔曲线连接两点,光点每帧取 curve.getPointAt(t) 的位置,Clock 驱动 t 循环。"
追问:getPointAt 和 getPoint 区别?(getPointAt 按弧长均匀取点,速度恒定;getPoint 按参数取,弧度处快)

**Q4:大屏特效性能怎么保证?**
一句话:"特效用 Basic 材质不受光、用 Points 合并调用、粒子关深度写、光源控制 1~2 个。"
追问:还有什么?(第10章:几何体合并、LOD、帧率监控)

**Q5:粒子能响应点击吗?**
一句话:"可以——把 Points 传进 Raycaster.intersectObjects,命中后通过顶点索引找到具体粒子。"
追问:大屏上"点一个光点看数据"怎么实现?(raycaster 拾取 + userData 或索引映射业务数据)
