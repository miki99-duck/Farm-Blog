# 第5章 纹理与贴图:给物体"穿衣服"

> 一句话讲清:**纹理(Texture)就是一张图片,贴到几何体表面当颜色——让物体从"纯色塑料"
> 变成"有花纹/有细节/会发光"的真实物体;TextureLoader 负责把图片加载成纹理。**
> 本章目标:会用 TextureLoader 贴图,掌握透明贴图/自发光/UV 概念,避开"加载跨域/方向反/不显示"的坑。

## 5.1 基本原理:图片 → 纹理 → 材质

```js
// 流程:图片文件 → THREE.Texture → 材质的 map 属性
const textureLoader = new THREE.TextureLoader();
const texture = textureLoader.load('textures/wall.jpg');   // 加载图片成纹理(异步,但用起来同步)

const material = new THREE.MeshStandardMaterial({
  map: texture,          // ★ map = 颜色贴图,物体表面就"长"这张图
  roughness: 0.6,
});
```

**map 是什么?** 材质表面颜色的来源。不设 map 时用 color 纯色;设了 map 后,
color 变成"染色基调"(白色=原图,其他色=叠加染色)。

```js
// color 与 map 的关系:color 是"滤镜"
new THREE.MeshStandardMaterial({ map: texture, color: 0xffffff });   // 原图颜色
new THREE.MeshStandardMaterial({ map: texture, color: 0xff0000 });   // 整张图偏红
```

### 常见贴图类型(材质的不同"通道")

| 属性 | 作用 | 例子 |
|------|------|------|
| `map` | 颜色贴图 | 墙面花纹、产品外观 |
| `normalMap` | 法线贴图:骗过光照,让平面有凹凸感 | 砖墙不用真建模,贴张法线图就有立体感 |
| `roughnessMap` | 粗糙度贴图 | 磨砂区域 vs 光滑区域 |
| `metalnessMap` | 金属度贴图 | 局部金属质感 |
| `emissiveMap` | 自发光贴图 | 屏幕、指示灯、发光文字 |

```js
// 法线贴图是"性能作弊神器":一个平面 + normalMap = 看起来凹凸不平的砖墙
const wall = new THREE.Mesh(
  new THREE.PlaneGeometry(4, 4),
  new THREE.MeshStandardMaterial({
    map: textureLoader.load('brick_color.jpg'),
    normalMap: textureLoader.load('brick_normal.jpg'),   // 不需要真的建模凹凸
  })
);
```

**面试考点:normalMap 原理?** 法线贴图存的是每个像素的"法线方向"数据,
光照计算时用这些"假法线"替代真实几何法线,让平面产生光影变化,看起来凹凸——但几何体本身是平的。
**好处**:顶点数不变,性能开销极小,却获得高模的视觉细节。

## 5.2 透明贴图:让物体"部分消失"(★ 高频)

```js
// 透明贴图场景:树木、栅栏、告警图标、粒子
// 准备一张"黑底白图案"的 PNG(白色=显示,黑色=透明)
const treeTexture = textureLoader.load('tree.png');

const treeMaterial = new THREE.MeshBasicMaterial({
  map: treeTexture,
  transparent: true,        // ★ 必须开
  side: THREE.DoubleSide,   // 十字交叉的两个面片都要能看到
  alphaTest: 0.5,           // 可选:alpha < 0.5 的像素直接丢弃(性能优化,避免透明排序问题)
});

// 树 = 两个交叉的平面(游戏里经典的"十字树"做法)
const tree = new THREE.Group();
const planeGeo = new THREE.PlaneGeometry(2, 3);
for (let i = 0; i < 2; i++) {
  const p = new THREE.Mesh(planeGeo, treeMaterial);
  p.rotation.y = (i * Math.PI) / 2;   // 两片平面成 90 度交叉
  tree.add(p);
}
scene.add(tree);
```

**alphaTest 是什么?** 像素 alpha 低于阈值就直接"不画"该像素。
**好处**:透明像素被丢弃,不参与渲染排序,避免透明物体之间"谁画谁后面"的闪烁问题。
**大屏粒子/告警图标强烈建议加 `alphaTest: 0.5`**——这是性能 + 视觉质量的双重优化。

## 5.3 自发光:让物体"亮"起来(不靠光源)

```js
// emissive(自发光):物体表面"自带亮度",但不照亮别人
const screen = new THREE.Mesh(
  new THREE.PlaneGeometry(3, 2),
  new THREE.MeshStandardMaterial({
    color: 0x000000,                       // 底色黑
    emissive: 0x00aaff,                    // 自发光颜色(蓝)
    emissiveMap: textureLoader.load('screen_ui.png'),  // 自发光贴图:哪亮哪暗
    emissiveIntensity: 1.5,                // 发光强度
  })
);

// 典型用途:大屏上的"设备面板屏幕""发光指示灯""发光边框"
// 注意:emissive 不影响周围物体(它不是光源),想照亮别人请用 PointLight
```

**emissive vs 光源的区别(面试高频):** emissive 只是把颜色"加"到物体表面,
它不会向周围发射光线、不会产生阴影。要"照亮环境"必须用真实光源。
记忆:**"emissive 是自己亮,光源是照亮别人。"**

## 5.4 UV:纹理是怎么"贴"到几何体上的?

**UV 是纹理坐标系**:每张图片都有 U(横向)、V(纵向)两个坐标(0~1),
几何体的每个顶点都有一个 UV 值,告诉 GPU"这个顶点对应图片的哪个位置"。

```
图片(纹理)坐标:           几何体表面:
(0,1) ---- (1,1)         顶点 A ↔ UV(0,0)  → 对应图片左下角
  |          |           顶点 B ↔ UV(1,0)  → 右下角
  |          |           顶点 C ↔ UV(0,1)  → 左上角
(0,0) ---- (1,0)         —— 三点定一个三角形,纹理就被"贴"上去了
```

```js
// 查看/修改 UV:几何体的 uv 属性是每个顶点的 UV 坐标数组
const geo = new THREE.BoxGeometry(1, 1, 1);
console.log(geo.attributes.uv);   // 24 个顶点(6 面 × 4 顶点)的 UV 数据

// 实际很少手改 UV —— 除非做"贴图局部显示"(如设备贴图上只显示告警区域)
// 面试能答出概念即可:UV 是纹理与几何体顶点之间的"对应关系"
```

**面试追问:BoxGeometry 的 6 个面贴同一张图怎么控制?** 默认每面都贴整张图;
要每面不同图,需要拆成 6 个 Plane 或修改 UV,或用多材质数组 `new THREE.Mesh([...])`。
(冷门,答出"UV 决定贴图位置"就够)

## 5.5 纹理加载的坑:跨域、方向、尺寸

| # | 坑 | 现象 | 解决 |
|---|----|------|------|
| 1 | 本地双击打开加载图片 | 报 CORS 跨域错 | 起本地服务:`npx serve .` 或 `python3 -m http.server` |
| 2 | 图片没加载完就渲染 | 物体是黑的/白模 | TextureLoader.load 有回调/onLoad,或直接忽略(下帧自动更新) |
| 3 | 纹理方向反了/旋转了 | 图案横七竖八 | `texture.rotation` / `texture.flipY` 调整(UV 原点约定不同) |
| 4 | 图片太大 | 加载慢、内存爆 | 图片压缩到 2048 以内;大屏用 1024 |
| 5 | 用了 map 但忘设 color 白色 | 图片发暗 | map 与 color:0xffffff 搭配;或调 material.color.set(0xffffff) |
| 6 | 透明图不透明 | 黑底方块 | `transparent: true` + PNG 要带 alpha 通道 |
| 7 | normalMap 效果不明显 | 平面太平 | 调 `material.normalScale.set(x, y)` 加大强度 |

## 5.6 面试自测(追问链)

**Q1:纹理是什么?怎么加载?**
一句话:"纹理是贴到物体表面的图片;TextureLoader.load 加载,赋给材质 map 属性。"
追问:加载是异步的吗?(是——load 是异步读文件,但 Three.js 会在纹理就绪后自动重绘,代码上可同步使用)

**Q2:map 和 color 的关系?**
一句话:"color 是基础色,map 是表面图片;设了 map 后 color 变成叠加滤镜,白色=原图。"
追问:想要原图颜色设什么?(color: 0xffffff)

**Q3:normalMap 是什么原理?**
一句话:"存每个像素的假法线方向,光照时用来计算光影,让平面看起来凹凸,但几何体还是平的。"
追问:好处?(顶点数不变、性能开销小,视觉细节大增)

**Q4:emissive 和光源的区别?**
一句话:"emissive 让自己表面亮,但不照亮别人;光源才向环境发射光线、产生阴影。"
追问:大屏的"发光屏幕"用什么?(MeshStandardMaterial + emissive/emissiveMap)

**Q5:UV 是什么?**
一句话:"UV 是纹理图片与几何体顶点之间的映射坐标(0~1),决定图片贴到表面哪个位置。"
追问:透明贴图为什么要 alphaTest?(丢弃低 alpha 像素,减少透明排序问题和性能开销)
