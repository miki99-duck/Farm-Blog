# 第3章 相机与控制器:从哪看、怎么转

> 一句话讲清:**相机是"眼睛"——透视相机像人眼(近大远小),正交相机像工程图(没透视);
> OrbitControls 是"鼠标控制器",让你用拖拽/滚轮自由旋转缩放视角。**
> 本章目标:搞懂两种相机 + 宽高比/裁剪面,会用 OrbitControls 做"可交互视角"。

## 3.1 透视相机 vs 正交相机:一个像眼睛,一个像图纸

```js
// 透视相机(默认选择):近大远小,像人眼看世界
// 参数: 视野角 fov(度) / 宽高比 aspect / 近裁剪面 near / 远裁剪面 far
const camera = new THREE.PerspectiveCamera(75, window.innerWidth / window.innerHeight, 0.1, 1000);

// 正交相机:没有透视,远处和近处一样大,像工程图/俯视图
// 参数: 左/右/上/下(视锥范围) / 近 / 远
const camera2 = new THREE.OrthographicCamera(-5, 5, 5, -5, 0.1, 100);
```

| 对比 | 透视相机 | 正交相机 |
|------|---------|---------|
| 效果 | 近大远小,有纵深感 | 无透视,等比例 |
| 参数 | fov/aspect/near/far | left/right/top/bottom/near/far |
| 用途 | 3D 场景默认、漫游、大屏主视角 | 2.5D 俯视图、地图、UI、等轴测 |

**fov(视野角)是什么?** 相机"张开的角度",角度越大看到的东西越多(但变形越夸张)。
75 度是常用值,大屏第一人称可 60~75。

**near/far(裁剪面)是什么?** 只渲染 [near, far] 范围内的物体,之外的直接丢弃(性能优化)。
**高频坑**:near 太大 → 近处物体被"切掉";far 太小 → 远处物体消失。默认 0.1/1000 够用,
但大场景(城市/厂区)要调大 far,否则远处设备突然消失。

## 3.2 相机的基本操作:位置 + 朝向

```js
camera.position.set(5, 4, 8);   // 把相机放到 (5,4,8)
camera.lookAt(0, 0, 0);          // 让相机"看向"原点 —— 不设置默认看向 -z 方向

// 常用:围绕原点转一圈(等距视角)
camera.position.set(10, 8, 10);
camera.lookAt(0, 0, 0);
```

**为什么"看向"很重要?** 相机默认朝向 -z 方向(屏幕里)。如果你把相机放到 (5,4,8) 但忘了 lookAt,
它仍然看向 -z,可能对着场景外面的空白——物体"在背后",什么都看不到。**凡是改了 position,
基本都要跟着 lookAt。**

## 3.3 OrbitControls:鼠标拖拽旋转、滚轮缩放(★ 最常用)

OrbitControls(轨道控制器)让场景"可操作":左键拖拽旋转、滚轮缩放、右键平移。
它不改变相机类型,只是每帧根据鼠标输入修改 camera 的位置/朝向。

```html
<script type="importmap">
  { "imports": {
      "three": "https://cdn.jsdelivr.net/npm/three@0.160.0/build/three.module.js",
      "three/addons/": "https://cdn.jsdelivr.net/npm/three@0.160.0/examples/jsm/"
  } }
</script>
<script type="module">
  import * as THREE from 'three';
  import { OrbitControls } from 'three/addons/controls/OrbitControls.js';  // ★ 单独导入

  // 三要素
  const scene = new THREE.Scene();
  const camera = new THREE.PerspectiveCamera(60, window.innerWidth / window.innerHeight, 0.1, 1000);
  camera.position.set(5, 4, 8);
  camera.lookAt(0, 0, 0);

  const renderer = new THREE.WebGLRenderer();
  renderer.setSize(window.innerWidth, window.innerHeight);
  document.body.appendChild(renderer.domElement);

  // ★ OrbitControls:传入相机 + 渲染器的 dom 元素
  const controls = new OrbitControls(camera, renderer.domElement);
  controls.enableDamping = true;      // 开启阻尼(惯性),手感更顺滑
  controls.dampingFactor = 0.05;      // 阻尼系数(越小越"粘")
  controls.minDistance = 2;           // 缩放下限(防止穿进物体)
  controls.maxDistance = 50;          // 缩放上限
  controls.maxPolarAngle = Math.PI / 2;  // 限制俯仰角(防止转到地下)

  // 场景内容:一个立方体 + 地面网格辅助线(看坐标用)
  scene.add(new THREE.Mesh(
    new THREE.BoxGeometry(1, 1, 1),
    new THREE.MeshStandardMaterial({ color: 0x3498db })
  ));
  scene.add(new THREE.GridHelper(10, 10));   // 地面网格:10x10 格
  scene.add(new THREE.AmbientLight(0xffffff, 0.5));
  scene.add(new THREE.DirectionalLight(0xffffff, 1));

  function animate() {
    requestAnimationFrame(animate);
    controls.update();   // ★ 阻尼模式下每帧必须调用 controls.update()
    renderer.render(scene, camera);
  }
  animate();
</script>
```

**OrbitControls 的三个高频坑:**

1. **忘了 `controls.update()`**:开了 damping(阻尼)后每帧必须 update,否则画面不动/抽搐。
2. **`enableDamping` 开了才顺滑**:不开阻尼,拖拽是"瞬间到位"的僵硬感。
3. **min/max 限制**:大屏场景建议设 `minDistance` 和 `maxPolarAngle`,
   否则用户滚轮能穿进设备里、或把视角转到地面以下。

## 3.4 常用相机辅助工具:调试神器

```js
// 1. 相机辅助:显示相机的"视锥体"(看相机朝向哪、裁剪范围多大)
scene.add(new THREE.CameraHelper(camera));

// 2. 坐标轴辅助:x 红 / y 绿 / z 蓝,一眼看出方向
scene.add(new THREE.AxesHelper(5));   // 长度 5 的三色坐标轴

// 3. 地面网格:铺在地上的网格线(判断高度/对齐)
scene.add(new THREE.GridHelper(10, 10));
```

**面试小考点:AxesHelper 三色对应?** x 轴红色、y 轴绿色、z 轴蓝色——这是 Three.js 的固定约定,
写代码、看截图都能直接对方向。

## 3.5 实战:透视/正交一键切换(大屏常见需求)

```js
// 大屏场景常用"3D 视角 + 2D 俯视"切换:
let useOrtho = false;
let orthoCamera, perspCamera;

// 初始化两种相机
perspCamera = new THREE.PerspectiveCamera(60, window.innerWidth / window.innerHeight, 0.1, 1000);
perspCamera.position.set(8, 6, 8);
perspCamera.lookAt(0, 0, 0);

const halfW = window.innerWidth / 2;
const halfH = window.innerHeight / 2;
orthoCamera = new THREE.OrthographicCamera(-halfW / 50, halfW / 50, halfH / 50, -halfH / 50, 0.1, 1000);
orthoCamera.position.set(0, 50, 0);   // 正上方俯瞰
orthoCamera.lookAt(0, 0, 0);

// 切换函数:换 activeCamera 并重建控制器(控制器绑定的是具体相机)
function switchCamera() {
  useOrtho = !useOrtho;
  const active = useOrtho ? orthoCamera : perspCamera;
  controls = new OrbitControls(active, renderer.domElement);
  controls.update();
}

// 渲染时用当前激活的相机
function animate() {
  requestAnimationFrame(animate);
  controls.update();
  renderer.render(scene, useOrtho ? orthoCamera : perspCamera);
}
```

## 3.6 常见坑汇总

| # | 坑 | 现象 | 解决 |
|---|----|------|------|
| 1 | 改了 position 忘 lookAt | 画面空白/物体在背后 | position 与 lookAt 成对设置 |
| 2 | 开了 damping 忘 update | 拖拽抽搐/不动 | 每帧 `controls.update()` |
| 3 | near 太大 | 近处物体被"切面" | near 用 0.1;大场景调 far 不调 near |
| 4 | far 太小 | 远处物体消失 | 厂区/城市场景 far 设 5000+ |
| 5 | fov 太大 | 画面畸变 | 第一人称 60~75;超过 100 变形严重 |
| 6 | 正交相机尺寸没随窗口变 | 缩放窗口后变形 | 监听 resize,重算 left/right/top/bottom(见第10章) |
| 7 | 忘导入 OrbitControls | 报错 "OrbitControls is not defined" | 从 'three/addons/controls/OrbitControls.js' 导入 |

## 3.7 面试自测(追问链)

**Q1:透视相机和正交相机区别?**
一句话:"透视相机近大远小,有纵深感;正交相机无透视,等比例——像人眼 vs 工程图。"
追问1:各自参数?(透视:fov/aspect/near/far;正交:left/right/top/bottom/near/far)
追问2:大屏俯视图用哪个?(正交——比例真实,适合 2.5D 地图)

**Q2:near/far 裁剪面是干嘛的?**
一句话:"只渲染 [near, far] 范围内的物体,之外丢弃,是性能优化手段。"
追问:near 设太大有什么问题?(近处物体被裁剪,出现"穿模/切面")

**Q3:OrbitControls 作用?为什么要有它?**
一句话:"把鼠标拖拽/滚轮变成相机旋转/缩放/平移,让用户自由观察 3D 场景。"
追问:damping 是什么?(惯性阻尼,开了手感顺滑,但要每帧 controls.update())

**Q4:相机为什么不设置 lookAt 会看不到物体?**
一句话:"相机默认朝向 -z 方向,物体可能在相机背后;lookAt 让相机看向指定目标。"
追问:改 position 后一定要 lookAt 吗?(不一定——如果目标位置没变,相机朝向不变就不用)

**Q5:怎么知道坐标轴方向?**
一句话:"AxesHelper 三色:x 红、y 绿、z 蓝;Three.js 是右手系。"
追问:z 轴朝哪?(朝屏幕外/朝你,右手定则)
